# 前端设计规范与审查标准

本目录为 MyTranslator 前端（网页端 + 桌面端 + 共享组件库）的设计权威来源，约束**设计阶段**与**代码完成后的审查阶段**。所有前端改动必须遵守本目录规范（AGENTS.md 强制）。

## 适用范围

### 本轮功能验证阶段（2026-09-12 用户确认）

开发中三个前端任务以功能接口验证为目标：编辑器暂用固定双栏，暂缓拖拽分栏、分栏比例持久化及视觉精修验收（《设计规范》§4.3 及相关视觉审查项）。对应代码必须留下 TODO，说明正式前端需要补齐的行为与规范位置；功能完成不代表这些视觉项目已完成。
仍须遵守共享 RCL/MudBlazor、资源文案、语义状态、占位符保护、保存与并发、危险操作确认、键盘可达及基本可访问性要求。已有主题直接复用，不引入第二套样式规范。
ROADMAP 将批量操作列在编辑器基础，本轮按该任务顺序实现（优先于《交互规范》§2 中的增强阶段描述）。

| 端 | 技术 | 适用性 |
|---|---|---|
| 网页端 | Blazor WebAssembly | 全部规范 |
| 桌面端 | .NET MAUI Blazor Hybrid | 全部规范（差异见《设计规范》§4.4） |
| 共享组件 | Razor Class Library | 全部规范 |

两端统一设计：一份规范、一套组件服务双端，设计时考虑两端通用性。

## 规范强制级别

- **必须（MUST）**：违反即审查不通过，对应审查标准"阻断 / 严重"级。
- **推荐（SHOULD）**：默认遵守，偏离需在审查中说明理由。

## 与 docs/back 的关系

- `docs/back` 定义接口契约与错误码；`docs/front` 定义界面呈现与交互。
- 前端不得自行解释错误码：错误文案一律由错误码映射产生（《交互规范》§3）。
- 前后端约定冲突时，先改契约文档再改代码，禁止单侧绕过。
