# 前端设计规范与审查标准

本目录为 MyTranslator 前端（网页端 + 桌面端 + 共享组件库）的设计权威来源，约束**设计阶段**与**代码完成后的审查阶段**。所有前端改动必须遵守本目录规范（AGENTS.md 强制）。

## 适用范围

### 功能验证阶段豁免的解除（2026-09-12）

上一轮开发中的三个前端任务曾以功能接口验证为目标：编辑器暂用固定双栏，暂缓拖拽分栏、分栏比例持久化及视觉精修验收（《设计规范》§4.3 及相关视觉审查项），代码以 `TODO(frontend-formal)` 标注。
正式前端轮次已补齐上述内容并移除全部 `TODO(frontend-formal)`：编辑器为可拖拽分栏（比例与折叠状态持久化到 localStorage），紧凑断点（1024–1280px）详情面板下叠，占位符在译文编辑面内以只读芯片内联呈现；看板、任务列表、术语提示与 Token 管理页按规范完成正式布局与视觉验收。双端仍须遵守共享 RCL/MudBlazor、资源文案、语义状态、占位符保护、保存与并发、危险操作确认、键盘可达及可访问性要求。

| 端 | 技术 | 适用性 |
|---|---|---|
| 网页端 | Blazor WebAssembly | 全部规范 |
| 桌面端 | .NET MAUI Blazor Hybrid | 全部规范（差异见《设计规范》§4.4） |
| 共享组件 | Razor Class Library | 全部规范 |

两端统一设计：一份规范、一套组件服务双端，设计时考虑两端通用性。

## 规范强制级别

- **必须（MUST）**：违反即审查不通过，对应审查标准"阻断 / 严重"级。
- **推荐（SHOULD）**：默认遵守，偏离需在审查中说明理由。

## 与 docs/back 的关系

- `docs/back` 定义接口契约与错误码；`docs/front` 定义界面呈现与交互。
- 前端不得自行解释错误码：错误文案一律由错误码映射产生（《交互规范》§3）。
- 前后端约定冲突时，先改契约文档再改代码，禁止单侧绕过。
