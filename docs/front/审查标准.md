# 前端审查标准

代码完成后的前端审查依据。与《设计规范》《组件规范》《交互规范》配套使用。

## 使用说明

- **时机**：每项前端功能完成时、合并/发布前必须执行。
- **输出**：逐条 `通过 / 不通过` + 证据（`文件:行号`）；存在"阻断"级不通过时不得交付。
- **严重度**：
  - **阻断**：功能不可用 / 违反本目录"必须（MUST）"级规范
  - **严重**：体验受损 / 规范偏离影响一致性
  - **一般**：规范偏离，可低成本修正
  - **建议**：优化项，不阻塞

## 维度一：需求符合

- [ ] 界面行为与 `docs/back` 接口契约一致（字段、状态、错误码映射）
- [ ] ROADMAP 对应验收项达成
- [ ] 401 自动跳登录；无 Token 访问受保护页被拦截
- [ ] 任务状态流转与后端一致；进度数字准确
- [ ] 编辑保存后刷新数据不丢失

## 维度二：规范符合

- [ ] 无硬编码色值/字号（全部走主题 token）
- [ ] 字体栈符合规范（UI / 等宽两栈，《设计规范》§3）
- [ ] 语义色按映射表使用（红=违规、琥珀=TM 告警、绿=确认、蓝=审核意见、灰=待确认）
- [ ] 断点与自适应手段符合规范（BreakpointProvider，无散落媒体查询）
- [ ] 通用能力使用 MudBlazor，无重复实现
- [ ] 领域组件复用 RCL，无页面内复制实现
- [ ] 用户可见字符串无硬编码（resx 检查为零，测试代码除外）

## 维度三：交互与状态

- [ ] 反馈分级正确（Snackbar / ErrorBanner / 骨架屏 / 按钮 loading / EmptyState，《交互规范》§3）
- [ ] 危险操作有 ConfirmDialog 且确认按钮语义正确（红字"确认"）
- [ ] 编辑器：切换即存、脏标记 `●`、确认状态流转正确
- [ ] 快捷键全部生效且与规范表一致；`?` 帮助可达
- [ ] 空态/加载/错误/失败态全覆盖，无空白页面

## 维度四：可访问性

- [ ] 全功能键盘可达；Tab 顺序合理；Esc 关闭弹窗/抽屉
- [ ] 焦点可见（focus ring 自定义样式）
- [ ] 状态三通道（颜色 + 图标 + 文字），不纯靠颜色
- [ ] 正文对比度 ≥ 4.5:1（亮 + 暗两主题）
- [ ] 表单控件有可见 label
- [ ] 关键图标有 aria-label
- [ ] 动态更新（进度 / Snackbar）在 aria-live 区域
- [ ] 触控目标 ≥ 24px（桌面场景）
- [ ] 弹窗聚焦陷阱 + 关闭后焦点归还
- [ ] 关键信息不依赖 hover 才能获得

## 维度五：工程质量

- [ ] 亮/暗双主题均过检（无对比度/可读性问题）
- [ ] 长列表虚拟化；无渲染风暴（确认每次渲染必要）
- [ ] 组件 CSS 隔离（.razor.css）；无行内样式堆积
- [ ] MudBlazor 版本全仓一致（RCL 与两端）
- [ ] 无死代码 / 注释掉的旧实现

## 附录：审查输出模板

```
## 审查结果
- 范围：<功能 / 提交>
- 结论：通过 / 不通过（阻断 N / 严重 N / 一般 N / 建议 N）

| 维度 | 条目 | 结果 | 证据 | 严重度 |
|---|---|---|---|---|
| 需求符合 | 401 跳登录 | 不通过 | Login.razor:42 未清理过期 Token | 严重 |

```

**阻断级不通过的处理**：修复后重新审查该项，直至通过方可交付。
