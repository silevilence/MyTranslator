# 规则检查接口约定

遵循《鉴权与基础接口约定》《文件导入拆解与导出接口约定》及 ADR-0002。所有调用要求 Bearer Token。

## 检查已保存分段

`POST /api/tasks/{taskId}/rule-checks`，JSON 请求：`{"extractionRevision":1}`。

成功 200：`taskId`、`extractionRevision`、`totalSegments`（不含受保护块）、`violatingSegments`、`enabledRules`、`items`。
`items` 仅包含违规分段，按 `order` 排序：`segmentId`、`order`、`version`、`violations`。
每条违规含 `ruleId`、`code`、`field`、`offset`、`length`。位置为 UTF-16 字符偏移，0 起算；`field=targetText`。
占位符结构违规是分段级诊断，`offset=0,length=0` 表示定位该分段，不声称定位某个错误字符。
缺失译文定位全部译文（null 时长度 0）。可由 `segmentId` 跳转编辑器；`version` 用于防止显示过期检查。

| ruleId | code | 判定 |
|---|---|---|
| placeholder_integrity | placeholder_integrity_violation | 真实引用必须与标记表及原文一致：重数、顺序、成对嵌套、自闭合种类。null 译文交缺失规则处理。|
| missing_translation | missing_translation | null、空白或剥离注册引用后仅剩空白。原译文相同可能是专名，不据此判漏翻。|

检查使用同一数据库读取快照，不修改状态/译文/版本，不存储结果，不与后台翻译或审核互斥；轮询期间可再次检查最新已提交译文。重提取后旧响应失效，编辑保存后应重新检查。TM 告警和 AI 审核意见不属于规则违规。

## 配置与扩展

`Rules:DisabledRules` 为规则 ID 数组（默认空，全部开启），环境变量示例 `Rules__DisabledRules__0=missing_translation`。此配置只影响诊断，不能关闭保存、翻译或导出的占位符安全校验。
新增实现 `ITranslationRule`（稳定 `Id`、`Evaluate`）并注册 DI 即会被引擎发现，无需改核心编排。规则同时供 AI 译文验证使用，纯确定性，不调用外部服务。

## 错误与前端映射

| HTTP | code | 中文文案 |
|---|---|---|
| 400 | invalid_extraction_revision | 提取修订无效，请刷新任务。|
| 404 | task_not_found | 任务不存在。|
| 409 | extraction_revision_changed | 分段已重新提取，请刷新任务。|

401 复用全局登录失效流程。`placeholder_integrity_violation` 显示“占位符被破坏”，`missing_translation` 显示“译文缺失”；均使用规则违规语义，不能当作 AI 审核意见。
