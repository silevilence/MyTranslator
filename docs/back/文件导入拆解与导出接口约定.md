# 文件导入拆解与导出接口约定

本文定义文件导入拆解模块及任务列表对 Web、桌面端和第三方系统公开的 REST 接口。接口覆盖上传/URL 导入、任务列表、分段预览、HTML 类任务重新提取和文件导出，并固化后续任务管理、翻译编辑器、AI 翻译及规则检查共同使用的分段契约。

鉴权、基础地址和通用 Problem Details 格式以[《鉴权与基础接口约定》](鉴权与基础接口约定.md)为准。本文所有接口均要求 Bearer Token。

## 1. 范围与接口原则

- 文件模块的公开接口负责把来源转换为任务中的分段和受保护块，并把译文回填为可下载文件。
- 任务是贯穿“导入 → 翻译 → 编辑 → 导出”的资源；文件模块不另建一套仅供前端使用的临时文件模型。
- Web、桌面端和第三方系统调用完全相同的接口。
- 分段的 `sourceText`、`markupTable`、`chapter` 和来源布局在一次提取修订内不可变；后续译文保存接口只能修改 `targetText` 和 `confirmationStatus`。
- 原文件字节、受保护块全文和回填模板由后端保存。调用方不得自行拼装导出文件。
- 本文定义任务列表及其进度、最新翻译运行摘要，但不定义人工译文保存等其他任务管理接口；后续接口不得改变本文的任务状态、进度及分段字段语义。

## 2. 通用约定

### 2.1 标识、时间与枚举

- `taskId`、`segmentId`、`protectedBlockId`、`previewId` 均为 UUID 字符串。
- 时间使用 UTC ISO 8601，例如 `2026-08-13T08:30:00Z`。
- 枚举值使用本文列出的英文小写字符串；调用方必须容忍未来增加未知枚举值。
- JSON 字段使用 `camelCase`。
- 请求和 JSON 响应使用 UTF-8；文件下载的编码规则见 §10。

### 2.2 分页

分段和来源布局均使用游标分页：

```http
GET /api/tasks/{taskId}/segments?limit=100&cursor={opaqueCursor}
```

- `limit` 默认 `100`，范围 `1..200`。
- `cursor` 是不透明字符串，调用方不得解析或构造。
- `nextCursor` 为 `null` 表示没有下一页。
- 游标绑定创建它的提取修订。重新提取后继续使用旧游标返回 `409 extraction_revision_changed`，调用方应从第一页重新加载。

任务列表同样使用 `limit`、不透明 `cursor` 和 `nextCursor` 形状，但不绑定单个任务的提取修订。任务列表游标绑定创建它时的状态筛选，并按 `createdAt`、`taskId` 记录稳定续页位置；更换筛选条件后调用方必须从第一页重新加载。

### 2.3 任务状态子集

本文响应中的 `status` 使用任务公共状态：

| 值 | 含义 |
|---|---|
| `created` | 导入完成，任务可预览或进入翻译 |
| `processing` | 正在执行翻译、审核等后台操作 |
| `completed` | 所有分段已有译文，可导出 |
| `failed` | 后台操作失败；详细原因由后续任务接口提供 |

文件解析在创建请求内同步完成。解析失败时不创建残留任务。

## 3. 支持的来源和文件类型

### 3.1 来源类型

| `source.kind` | 说明 |
|---|---|
| `file` | 浏览器、桌面端或第三方系统上传的文件 |
| `url` | 后端通过静态 HTTP GET 获取的 HTML 页面 |

### 3.2 文件类型

`fileType` 只接受：

| 值 | 常见扩展名 | 可用来源 |
|---|---|---|
| `txt` | `.txt` | 文件 |
| `markdown` | `.md`、`.markdown` | 文件 |
| `html` | `.html`、`.htm` | 文件、URL |
| `epub` | `.epub` | 文件 |

调用方可显式传入 `fileType`。未传时按以下顺序推断：

1. 文件名或 URL 最终地址的扩展名；
2. 上传 part 的 `Content-Type` 或 URL 响应的 `Content-Type`；
3. 仍无法唯一确定时返回 `400 unable_to_infer_file_type`。

显式类型优先于扩展名和媒体类型，但内容必须能按该类型解析；否则返回 `422 import_parse_failed`。URL 导入只允许 `html`，显式指定其他类型返回 `400 invalid_file_type_for_url`。

## 4. 创建导入任务

### 4.1 上传文件

`POST /api/tasks/imports/file`

请求为 `multipart/form-data`：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `file` | binary | 是 | 原始文件；每次请求仅允许一个文件 |
| `fileType` | string | 否 | `txt` / `markdown` / `html` / `epub` |
| `segmentationMode` | string | 否 | 仅 txt 可用：`paragraph` / `line`；未传则采用智能推荐 |

示例：

```bash
curl -X POST http://localhost:5199/api/tasks/imports/file \
  -H "Authorization: Bearer sk-dev-00000000000000000000000000000000" \
  -F "file=@manual.md;type=text/markdown" \
  -F "fileType=markdown"
```

对非 txt 文件传 `segmentationMode` 返回 `400 segmentation_mode_not_applicable`，避免调用方误以为该参数已生效。

单次上传默认上限为 `10 MiB`；后端即使收到不可信或缺失的 `Content-Length`，也会在流式读取过程中执行同一上限。部署调整上限时，前端应从后续能力接口读取，不得写死为更大的值。

### 4.2 从 URL 导入

`POST /api/tasks/imports/url`

```json
{
  "url": "https://example.com/guide.html",
  "fileType": "html"
}
```

- `url` 必须是绝对 `http` 或 `https` 地址，不允许用户信息、片段标识或 `file:` 等其他协议。
- 后端使用浏览器风格 `User-Agent`，跟随有限次重定向；每次重定向都重新执行地址安全检查。
- 后端流式读取并强制执行超时与大小上限，不信任 `Content-Length`。
- URL 响应正文默认上限为 `10 MiB`。
- 禁止访问回环、链路本地、私有网络、云元数据地址及解析到这些地址的域名，以避免 SSRF；DNS 解析结果和实际连接地址均须校验。
- 仅做静态 GET，不执行 JavaScript。页面没有可译正文且主要内容依赖脚本时返回 `422 dynamic_page_not_supported`。
- 保存最终响应地址和重定向后的 HTML；导出只生成下载文件，不向来源网站发起写请求。

### 4.3 创建成功响应

成功返回 `201 Created`，并设置：

```http
Location: /api/tasks/4d898d78-1f24-47e9-8e30-adcee716c13d
```

响应体为导入摘要：

```json
{
  "taskId": "4d898d78-1f24-47e9-8e30-adcee716c13d",
  "status": "created",
  "source": {
    "kind": "file",
    "fileName": "manual.txt",
    "requestedUrl": null,
    "finalUrl": null,
    "mediaType": "text/plain",
    "byteLength": 18240
  },
  "fileType": "txt",
  "originalEncoding": "utf-8",
  "extractionRevision": 1,
  "segmentation": {
    "requested": null,
    "recommended": "paragraph",
    "effective": "paragraph",
    "reason": "blank_line_blocks_present"
  },
  "counts": {
    "segments": 42,
    "protectedBlocks": 7,
    "chapters": 0
  },
  "capabilities": {
    "canReextract": false,
    "canExport": false
  },
  "createdAt": "2026-08-13T08:30:00Z"
}
```

约束：

- `segmentation` 仅 txt 非空。`requested` 是调用方传值；未传时为 `null`，且 `effective` 等于 `recommended`。
- `reason` 当前值为 `blank_line_blocks_present` 或 `few_or_no_blank_lines`。
- `originalEncoding` 使用小写 IANA 编码名；epub 容器内可能有多个 XHTML 编码，因此该字段为 `null`。
- `extractionRevision` 从 `1` 开始，每次应用重新提取后递增。
- `canReextract` 对 html 文件、URL HTML 和 epub 为 `true`，对 txt/markdown 为 `false`。
- `canExport` 表示当前是否满足 §10 的公开导出条件，不代表底层是否能进行无译文回填测试。
- URL 来源的 `fileName` 为后端生成的建议下载名；文件来源的 `requestedUrl`、`finalUrl` 为 `null`。

### 4.4 读取任务摘要

`GET /api/tasks/{taskId}`

成功返回 `200 OK` 和 §4.3 相同形状的当前摘要。因此创建响应的 `Location` 始终指向可读取的任务资源。后续任务管理接口可在该响应中增加进度、失败原因等可选字段，但不得改变本文既有字段语义。

### 4.5 列出任务

`GET /api/tasks?status={status}&limit={limit}&cursor={opaqueCursor}`

该接口按 `createdAt` 降序、相同时间按 `taskId` 降序返回任务，供 Web、桌面端和第三方系统加载任务列表。请求字段：

| 查询参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `status` | string | 否 | 单值状态筛选：`created` / `processing` / `completed` / `failed`；不传表示全部任务 |
| `limit` | integer | 否 | 默认 `100`，范围 `1..200` |
| `cursor` | string | 否 | 上一页返回的不透明游标；必须与当前 `status` 筛选一致 |

示例：

```bash
curl "http://localhost:5199/api/tasks?status=processing&limit=20" \
  -H "Authorization: Bearer sk-dev-00000000000000000000000000000000"
```

成功返回 `200 OK`：

```json
{
  "items": [
    {
      "taskId": "4d898d78-1f24-47e9-8e30-adcee716c13d",
      "status": "processing",
      "source": {
        "kind": "file",
        "fileName": "manual.txt",
        "requestedUrl": null,
        "finalUrl": null,
        "mediaType": "text/plain",
        "byteLength": 18240
      },
      "fileType": "txt",
      "extractionRevision": 1,
      "progress": {
        "completedSegments": 24,
        "totalSegments": 42
      },
      "latestTranslationRun": {
        "runId": "56ccae85-4fea-43d6-a736-644ac9ea2422",
        "status": "processing",
        "progress": {
          "processedSegments": 24,
          "succeededSegments": 23,
          "failedSegments": 1,
          "percent": 60.0
        },
        "failure": null,
        "createdAt": "2026-08-14T08:30:00Z",
        "finishedAt": null
      },
      "createdAt": "2026-08-13T08:30:00Z"
    }
  ],
  "nextCursor": null
}
```

字段约束：

| 字段 | 约束 |
|---|---|
| `source` | 与 §4.3 同形状，调用方可直接显示来源文件名并保留 URL 来源信息 |
| `progress.completedSegments` | 当前提取修订内 `targetText != null` 的分段数；人工确认状态不影响该计数 |
| `progress.totalSegments` | 当前提取修订内全部可译分段数 |
| `latestTranslationRun` | 按 `createdAt`、`runId` 降序选取当前提取修订的最新运行；无运行时为 `null` |
| `latestTranslationRun.status` | 复用[《AI 翻译接口约定》](AI%20翻译接口约定.md) §2.3 的运行状态 |
| `latestTranslationRun.progress` | 复用《AI 翻译接口约定》§4 的运行进度形状和计算语义 |
| `latestTranslationRun.failure` | 复用《AI 翻译接口约定》§10.2 的运行失败摘要；活动或成功运行时为 `null` |

边界行为：

- 没有匹配任务时返回 `200 OK`、空 `items` 和 `nextCursor = null`。
- 列表项是一次请求时的数据库快照；调用方刷新页面时从第一页重新加载，不依赖本地缓存推断任务状态或进度。
- 续页游标使用最后一项的 `createdAt` 和 `taskId` 定位，因此第一页加载后新创建的任务不会造成既有任务在后续页重复或跳过。
- 游标无法解析、不属于任务列表或与当前 `status` 筛选不一致时返回 `400 invalid_cursor`。
- `status` 不在任务公共状态集合时返回 `400 invalid_task_status`。

## 5. 各格式拆解规则

### 5.1 txt

`paragraph`（段落式）：

- 一个或多个空行（包括只含空白字符的行）分隔段落。
- 段落内部软换行及其原始换行符保留在 `sourceText`。
- 空白块不产生分段，作为来源布局中的受保护块原位保存。
- 超长段落不二次切分；超出任务级文本上限时整次导入失败，不静默改用其他模式。

`line`（换行式）：

- 每个含可译内容的物理行为一个分段。
- 行尾符不进入可译文本，由回填模板保存。
- 空行不产生分段，作为受保护块原位保存。

智能推荐是确定性的：检测到空行块时推荐 `paragraph`；几乎没有空行时推荐 `line`。推荐只影响未显式指定模式的请求。

### 5.2 markdown

- 以空行形成的块为基础，再按块级语法逐行确定分段。
- 标题、列表项、引用和表格结构等块级标记进入该行分段的占位符；调用方看到的是 `<xN>` / `</xN>` / `<xN/>` 引用，而不是可编辑的原标记。
- 行内强调、链接、图片等不可译结构按 §7 的标记表表示；链接目标和图片地址不翻译。
- 围栏代码块、缩进代码块、分隔线和内嵌 HTML 块不产生分段，作为受保护块保存。
- 只有结构标记而没有可译文本的行不产生分段，整体作为受保护块保存。

### 5.3 html

- 默认只提取 `body` 内可译文本。
- `script`、`style`、`noscript`、`template`、`iframe`、`svg`、`pre`、`code` 元素及其内容不翻译，作为受保护内容原位保存。
- 块级元素确定分段边界；标签和 HTML 实体全部占位符化。
- 元素属性不翻译，包括 `alt`、`title`、`placeholder` 和 `aria-label`。
- 解析基于 HTML 语法树，不以正则表达式修改 HTML。
- 保留 doctype、注释、属性顺序/引号、原始实体、换行和所有未翻译字节；回填只替换可译文本对应的字节范围。

### 5.4 epub

- 按 OPF spine 顺序处理 XHTML 内容项，每个内容项走同一 HTML 管道。
- `nav.xhtml` 参与翻译；不在 spine 中时仍记录为 `role = navigation` 的文档部分。
- OPF 元数据、CSS、图片、字体及其他未翻译资源不产生分段，导出时原样字节拷贝。
- 分段和受保护块携带 §8 的章/文档部分归属。
- 导入须防御 ZIP Slip、超量 entry、异常压缩比和解压后总大小超限；不合法 epub 返回 `422 import_parse_failed`。
- 默认最多接受 `10,000` 个 ZIP entry，解压后总大小上限为 `200 MiB`；原始 epub 上传仍受 §4.1 的上传上限约束。

## 6. 读取分段

`GET /api/tasks/{taskId}/segments`

该接口只返回可译分段，供虚拟化分段列表、AI 翻译和规则检查使用：

```json
{
  "extractionRevision": 1,
  "totalCount": 42,
  "items": [
    {
      "id": "7d59abcf-eaf4-42d3-b1fe-f78bf08ca72b",
      "order": 1,
      "sourceText": "<x7>Read<x12/>this</x7>",
      "targetText": null,
      "confirmationStatus": "pending",
      "version": 1,
      "markupTable": [
        {
          "id": 7,
          "kind": "paired",
          "openingText": "<strong>",
          "closingText": "</strong>",
          "originalText": null,
          "meaning": "加粗强调"
        },
        {
          "id": 12,
          "kind": "standalone",
          "openingText": null,
          "closingText": null,
          "originalText": "&nbsp;",
          "meaning": "不间断空格"
        }
      ],
      "chapter": null
    }
  ],
  "nextCursor": "eyJyZXZpc2lvbiI6MS4uLn0"
}
```

字段约束：

| 字段 | 约束 |
|---|---|
| `order` | 当前提取修订内从 1 开始、连续递增；重新提取后可变化 |
| `sourceText` | 可译原文，含与 `markupTable` 对应的占位符引用 |
| `targetText` | 译文；尚未翻译时为 `null`，不得用空字符串代替未翻译 |
| `confirmationStatus` | `pending` / `translated` / `confirmed` |
| `version` | 乐观并发版本；后续保存译文成功后递增 |
| `markupTable` | 本分段只读标记表；编号只在本分段内有效 |
| `chapter` | 非 epub 为 `null`；epub 见 §8 |

`segmentId` 在当前提取修订内稳定。应用重新提取后会生成一组新的 ID，旧 ID 不得复用。

## 7. 占位符与标记表契约

占位符语法固定为：

- 成对开始：`<xN>`
- 成对结束：`</xN>`
- 独立标记：`<xN/>`
- `N` 是正整数，与同一分段 `markupTable[].id` 对应。

标记项有两种合法形状：

| `kind` | 必填字段 | 对应引用 |
|---|---|---|
| `paired` | `openingText`、`closingText` | `<xN>...</xN>` |
| `standalone` | `originalText` | `<xN/>` |

其他形状字段为 `null`。每个标记出现位置分配独立 ID；ID 不保证连续。成对引用必须正确嵌套，不允许交叉。

字面文本也可能恰好是 `<x1>`。判断规则是：只有能与该分段 `markupTable` 中同 ID、同种类记录对应的完整引用才是占位符；其他文本按普通可译字符处理。后端分配 ID 时必须避开会与原文字面量形成歧义的编号。前端和第三方调用方必须根据标记表渲染和校验，禁止仅用正则把所有 `<x数字>` 当作标记。

`markupTable` 是只读数据。AI 翻译或人工编辑不得新增、删除、改写引用，也不得改变成对关系。后端保存和导出前均须验证；违规属于规则违规，不能因调用方提交了字符串而覆盖标记表。

## 8. epub 章/文档部分归属

epub 分段的 `chapter` 结构为：

```json
{
  "id": "1be25e73-aa05-4de0-9b1d-43031f058eef",
  "order": 3,
  "spineIndex": 2,
  "resourcePath": "OEBPS/chapter-02.xhtml",
  "title": "第二章",
  "role": "content"
}
```

- `order` 是本次导入中可翻译 XHTML 文档部分的顺序，从 1 开始。
- `spineIndex` 是零基 spine 下标；不在 spine 中的导航文档为 `null`。
- `resourcePath` 是 epub 包内规范化相对路径，不是主机文件路径。
- `title` 无法可靠推断时为 `null`。
- `role` 为 `content` 或 `navigation`。

同一文档部分的分段共享相同 `chapter.id`。调用方按 `chapter.order`、再按分段 `order` 展示；不得根据 ZIP entry 顺序推断阅读顺序。

        "type": "markdownCodeBlock",
        "previewText": "```csharp\n...",
        "byteLength": 684,
        "contentHash": "sha256:73c3...",
        "chapter": null
      },
      "segment": null
    },
    {
      "order": 2,
      "kind": "segment",
      "protectedBlock": null,
      "segment": {
        "id": "7d59abcf-eaf4-42d3-b1fe-f78bf08ca72b",

        "version": 1,
        "markupTable": [],
        "chapter": null
      }
    }
  ],
  "nextCursor": null
}
```

- 联合视图的 `order` 与分段自身 `order` 是两个序列：前者覆盖所有来源单元，后者只覆盖可译分段。
- `previewText` 只用于展示，可截断且不保证包含受保护块全文。
- `contentHash` 基于后端保存的完整原始字节计算。
- 受保护块内容不可通过修改分段接口写入；导出始终使用后端保存的原始字节。

## 10. 导出

`GET /api/tasks/{taskId}/export`

成功返回 `200 OK` 二进制内容，并设置正确的 `Content-Type` 与安全的下载文件名：

```http
Content-Type: text/html; charset=utf-8
Content-Disposition: attachment; filename="guide.translated.html"; filename*=UTF-8''guide.translated.html
```

导出条件：

- 每个分段的 `targetText` 均包含非空白译文；人工 `confirmed` 不是导出的必要条件。
- 所有译文占位符与只读标记表一致且正确嵌套。
- 没有正在改变分段或译文的后台操作。

不满足时返回 `409 task_not_exportable`，Problem Details 的 `errors` 扩展给出缺失译文数、占位符违规数等可操作信息。

格式保证：

- txt/markdown/html 使用导入时保存的编码、BOM、换行和回填模板；除译文替换范围外，其余原始字节不变。
- 译文字符无法用原编码表示时返回 `422 target_encoding_unrepresentable`，不静默替换字符或擅自转换整个文件编码。
- 未替换任何可译文本的内部回填结果必须与 txt/markdown/html 原文件逐字节一致；该不变量用于后端测试，不放宽公开接口的完整译文条件。
- epub 重建 ZIP 时 `mimetype` 必须是首个 entry 且不压缩；未修改资源逐字节拷贝，仅对有译文的 XHTML 内容回填。
- URL 导出为完整 HTML 下载文件，不回写网页。

建议文件名：上传文件在原 basename 后加 `.translated`；URL 使用最终地址可用 basename，无法取得时使用 `translated-page.html`。服务端必须清理路径分隔符和控制字符。

## 11. HTML 类任务重新提取

重新提取只适用于 `canReextract = true` 的任务，严格分为“创建预览”和“应用预览”两步。预览不会修改任务。

### 11.1 创建预览

`POST /api/tasks/{taskId}/extraction-previews`

```json
{
  "selector": "main article, nav[aria-label='Table of contents']"
}
```

语义：

- 选择器作用于 HTML `body`；epub 对每个参与翻译的 XHTML 文档部分分别执行。
- 多个匹配或嵌套匹配按文档顺序去重，不重复生成分段。
- 匹配范围内仍执行 §5 的排除规则；范围外内容成为受保护内容并在导出时保留。
- 空选择器、语法错误或不受支持的选择器返回 `400 invalid_selector`；语法合法但全局无匹配返回 `422 selector_no_match`。
- 创建预览时记录任务的 `baseExtractionRevision`。预览有服务端过期时间，不承诺跨应用重启保留。

成功返回 `201 Created`：

```http
Location: /api/tasks/4d898d78-1f24-47e9-8e30-adcee716c13d/extraction-previews/9a882f4c-b06a-4a86-9b8a-39b3dcd3a066
```

```json
{
  "previewId": "9a882f4c-b06a-4a86-9b8a-39b3dcd3a066",
  "taskId": "4d898d78-1f24-47e9-8e30-adcee716c13d",
  "selector": "main article, nav[aria-label='Table of contents']",
  "baseExtractionRevision": 1,
  "counts": {
    "segments": 31,
    "protectedBlocks": 12,
    "chapters": 4
  },
  "translationLoss": {
    "translatedSegments": 18,
    "confirmedSegments": 6,
    "requiresConfirmation": true
  },
  "expiresAt": "2026-08-13T08:45:00Z"
}
```

使用以下接口读取尚未过期的同一预览摘要；成功形状与创建响应相同：

```http
GET /api/tasks/{taskId}/extraction-previews/{previewId}
```

预览分段使用：

```http
GET /api/tasks/{taskId}/extraction-previews/{previewId}/segments?limit=100&cursor=...
```

响应分页形状与 §6 相同，但新分段的 `targetText` 均为 `null`、`confirmationStatus` 均为 `pending`；预览分段 ID 不得当作应用后的正式 ID。

### 11.2 应用预览

`POST /api/tasks/{taskId}/extraction-previews/{previewId}/apply`

```json
{
  "confirmTranslationLoss": true
}
```

应用时后端必须再次检查任务当前状态和数据损失，而不是只信任预览时的计数：

- 存在任何已翻译或已确认分段且 `confirmTranslationLoss` 不是 `true` 时返回 `409 translation_loss_confirmation_required`，并返回最新计数。
- 当前 `extractionRevision` 与预览的 `baseExtractionRevision` 不同，返回 `409 extraction_preview_stale`。
- 任务正在执行翻译、审核、导出或其他互斥操作时返回 `409 task_busy`。
- 预览已过期时返回 `410 extraction_preview_expired`。

成功返回 `200 OK` 和 §4.3 的导入摘要，同时：

- 原任务 ID 保持不变；`extractionRevision` 加 1。
- 原分段、译文、确认状态以及依赖旧分段 ID 的规则结果、TM 匹配、AI 审核意见全部失效并删除。
- 新分段取得新的正式 ID，状态为 `pending`，任务状态重置为 `created`。
- 原文件/URL 响应以及范围外内容仍由后端保留，导出结果仍是完整文件。

## 12. 错误码

本文在通用 Problem Details 上增加稳定的 `code` 字段；字段级或统计信息放在 `errors` 扩展中。前端按 `code` 映射文案，`title`/`detail` 仅用于诊断。

```json
{
  "type": "https://mytranslator.local/problems/translation-loss-confirmation-required",
  "title": "Translation loss confirmation required",
  "status": 409,
  "code": "translation_loss_confirmation_required",
  "instance": "/api/tasks/4d898d78-1f24-47e9-8e30-adcee716c13d/extraction-previews/9a882f4c-b06a-4a86-9b8a-39b3dcd3a066/apply",
  "errors": {
    "translatedSegments": 18,
    "confirmedSegments": 6
  }
}
```

| HTTP | `code` | 场景 |
|---|---|---|
| 400 | `invalid_file_type` | `fileType` 不在允许集合 |
| 400 | `invalid_file_type_for_url` | URL 请求指定了非 html 类型 |
| 400 | `unable_to_infer_file_type` | 扩展名和媒体类型均无法唯一推断 |
| 400 | `invalid_segmentation_mode` | txt 分段模式值无效 |
| 400 | `segmentation_mode_not_applicable` | 非 txt 请求携带分段模式 |
| 400 | `invalid_selector` | CSS 选择器为空、语法错误或不受支持 |
| 400 | `invalid_source_url` | URL 格式或协议不合法 |
| 400 | `unsafe_source_url` | URL 或重定向目标指向禁止访问的网络地址 |
| 400 | `invalid_cursor` | 分页游标不可解析或不属于当前资源 |
| 400 | `invalid_pagination` | 分页 `limit` 不在 `1..200` 范围内 |
| 400 | `invalid_task_status` | 任务列表 `status` 不在任务公共状态集合 |
| 404 | `task_not_found` | 任务不存在 |
| 404 | `extraction_preview_not_found` | 预览不存在或不属于该任务 |
| 409 | `task_busy` | 任务正在执行互斥操作 |
| 409 | `reextraction_not_supported` | txt/markdown 任务请求重新提取 |
| 409 | `task_not_exportable` | 译文不完整或占位符不合法 |
| 409 | `translation_loss_confirmation_required` | 重新提取将丢失已有译文但未确认 |
| 409 | `extraction_preview_stale` | 任务已应用过其他重新提取 |
| 409 | `extraction_revision_changed` | 分页期间提取修订已变化 |
| 410 | `extraction_preview_expired` | 重新提取预览已过期 |
| 413 | `content_too_large` | 上传、URL 响应或 epub 解压内容超过配置上限 |
| 415 | `unsupported_media_type` | 请求媒体类型不受支持 |
| 422 | `import_parse_failed` | 内容损坏或无法按选定类型解析 |
| 422 | `selector_no_match` | CSS 选择器在所有目标文档中均无匹配 |
| 422 | `dynamic_page_not_supported` | URL 页面依赖 JavaScript 才能产生正文 |
| 422 | `target_encoding_unrepresentable` | 译文无法用原文件编码表示 |
| 502 | `source_fetch_failed` | URL DNS、连接、TLS、重定向或非成功响应失败 |
| 504 | `source_fetch_timeout` | URL 获取超过服务端超时 |

服务器不得在错误响应中泄漏主机文件路径、解析器堆栈、内网探测细节或 URL 请求中可能包含的凭据。

## 13. 调用流程

### 13.1 文件/URL 导入到导出

1. 调用 `POST /api/tasks/imports/file` 或 `POST /api/tasks/imports/url` 创建任务。
2. 使用 `GET /api/tasks/{taskId}/segments` 分页展示并取得公共分段契约。
3. 通过后续 AI 翻译或人工编辑接口写入 `targetText`；不得修改标记表。
4. 任务满足导出条件后调用 `GET /api/tasks/{taskId}/export` 下载文件。

### 13.2 重新提取

1. 检查创建响应中的 `capabilities.canReextract`。
2. 调用 `POST /api/tasks/{taskId}/extraction-previews` 创建选择器预览。
3. 分页读取预览分段并向用户展示 `translationLoss`。
4. 用户明确接受损失后调用 `/apply`，必要时传 `confirmTranslationLoss: true`。
5. 应用成功后丢弃本地旧分段和游标，从正式分段第一页重新加载。

## 14. 与相关任务的契约衔接

| 相关任务 | 必须复用的字段/规则 |
|---|---|
| AI 全自动翻译 | 输入 `sourceText`；输出必须保留 `markupTable` 对应引用 |
| 翻译编辑器基础 | 读取分段 `id`、`sourceText`、`targetText`、`confirmationStatus`、`version` 和 `markupTable`；标记表只读 |
| 硬性规则检查 | 以 `markupTable` 校验引用新增/删除/改写、成对性和顺序；以 `targetText = null` 或空白检测漏翻 |
| 任务列表 | 复用 `taskId`、任务状态、提取修订和分页约定；进度按当前分段译文计算，最新运行摘要复用 AI 翻译契约 |
| 后续任务管理与开放 REST | 复用 `taskId`、任务状态、提取修订、分段 ID 和分页约定，不另建内部接口 |
| epub 编辑/预览 | 使用 `chapter.order` / `spineIndex` / `role`，不根据 ZIP entry 顺序排序 |

上述相关任务若扩展响应，只能新增可选字段或新资源；不得改变占位符语法、标记表只读性、受保护块不可编辑性及重新提取会替换分段 ID 的语义。
