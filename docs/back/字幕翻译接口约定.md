# 字幕翻译接口约定

本增量契约适用于 Web、桌面端及第三方系统。鉴权、基础地址及 Problem Details 以《鉴权与基础接口约定》为准，全部接口要求 Bearer Token；分段、游标、版本、确认及运行状态沿用既有契约。JSON 使用 UTF-8、camelCase、小写枚举；标识为 UUID，运行时间为 UTC ISO 8601。

## 范围与导入

`POST /api/tasks/imports/file` 的 multipart `fileType` 新增 `srt`、`vtt`；缺省先按 `.srt` / `.vtt` 扩展名，再按 `application/x-subrip` / `text/vtt` 推断。显式类型优先。字幕 `segmentation=null`、`canReextract=false`，传 txt 分段模式仍返回 `400 segmentation_mode_not_applicable`。`POST /api/tasks/imports/files` 支持与既有格式混合，限制及原子性不变。

```bash
curl http://localhost:5199/api/tasks/imports/file \
  -H "Authorization: Bearer …" -F "file=@captions.srt" -F "fileType=srt"
```

成功 201 返回既有任务摘要，`fileType=srt` 或 `vtt`。一条含可译文本的字幕条目对应一个完整分段，条目内多行不再拆分。序号/标识、起止时间、定位设置、条目分隔符及无可译文本的条目均受保护，不发送给 AI。分段顺序按原文件顺序；合法时间重叠不拒绝、不修正。时间必须结束晚于开始，分秒在 00–59；VTT 起始时间须非递减。不支持时间轴编辑、拆并条目、跨格式或双语导出。

SRT 支持 UTF-8（有/无 BOM）、带 BOM 的 UTF-16 LE/BE；VTT 只支持 UTF-8（有/无 BOM）。严格解码，拒绝损坏编码、UTF-32、无 BOM 的 UTF-16 及旧编码猜测。保留原编码、BOM、正文以外全部字节、LF/CRLF/CR 与文件末尾无换行。字幕正文允许调整合法断行，导出新增断行使用该条目原时间轴行的换行符；回填完全相同原文时保留原正文混合换行。

## 支持的结构

- SRT：十进制非负序号、`HH:MM:SS,mmm --> HH:MM:SS,mmm` 时间轴；支持配对嵌套的 `b`、`i`、`u` 以及仅带 `color` 的 `font`（常用颜色名或 `#RRGGBB`）。不支持 ASS 覆盖块、坐标扩展、未知标签或破损嵌套。
- VTT：`WEBVTT` 签名及同一行说明；保留 `NOTE`、首条字幕之前的 `STYLE` / `REGION` 块、条目标识及合法定位设置。时间为 `MM:SS.mmm` 或 `HH:MM:SS.mmm`。支持 `b/i/u/c/ruby/rt/v/lang` 正文标签、类名、说话人和语言注释以及条目时间范围内严格递增的段内时间标记；标签须配对，整条目外层 `v` / `lang` 可省略闭标签。支持 `vertical/line/position/size/align/region` 设置，未知或重复设置拒绝。
- VTT 块间空行必须是完全空行，首版拒绝只含空格或制表符的行，避免应用与播放器对条目边界作出不同解释。
- 实体：两种格式支持 `&amp; &lt; &gt; &nbsp; &lrm; &rlm;`；SRT 另支持 `&quot; &apos;` 与合法数字实体。标签、实体和段内时间标记全部按 ADR-0002 占位符化并原样回填，不能增删、改写、重排。未知实体或裸露的 `<` / `&` 拒绝，SRT 的 ASS 花括号控制语法拒绝。
- 首版仅导入字幕轨道。WebVTT 标准没有可可靠自动推断用途的文件内必填标识；调用本接口即声明它是字幕，调用方不得将 metadata/chapters 轨道传入。明确声明 `Kind: metadata` / `Kind: chapters` 的头部拒绝；其余非空多行头部字段也不在首版范围内。不得依据 JSON 长相猜测或改写正文。

## 保存、翻译、确认及导出

沿用 PUT segments、POST translation-runs / segment-confirmations / review-runs 及 GET result。审核只产出意见，不改变字幕结构。人工保存/批量确认、AI 成功落库、导出均执行占位符与字幕正文安全校验；多文件按持久化成员类型校验，不凭文件扩展名猜测。译文不得含空白行、首尾换行、`-->`、新标签/实体/控制语法或非法控制字符（允许制表符与合法换行）。只含标记无可译内容仍按 missing_translation 拒绝；清空译文仍用 null/pending。

手动保存失败不改变译文、确认状态或版本，前端保留草稿；AI 无效结果按既有有限重试与分段级部分失败处理。缺失/重复分段沿用 llm_response_invalid。受保护块不计入进度。

GET result / export 返回 SRT `application/x-subrip; charset=<原编码>`、VTT `text/vtt; charset=utf-8`，下载扩展名按实际格式为 `.srt` / `.vtt`，即使显式导入时文件名后缀不一致。多文件 ZIP 保留原成员名，若显式类型与后缀不一致只涉及单文件接口；ZIP 成员各自沿用相同校验、编码及回填行为。原文回填须逐字节一致。

允许的跨源浏览器调用可读取 `Content-Disposition`、`Location` 和 `Retry-After` 响应头；下载名取自后端 Content-Disposition，不能因前后端分端口部署而丢失扩展名。

## 错误码

| HTTP | code | 含义 / 建议文案 |
|---|---|---|
| 422 | subtitle_parse_failed | 字幕格式或时间轴无效，请检查原文件。附 errors.fileType、cue（1 起算）、line（1 起算）以定位输入。|
| 422 | subtitle_encoding_invalid | 字幕编码不受支持或内容损坏，请使用 UTF-8；SRT 也支持带 BOM 的 UTF-16。|
| 422 | subtitle_structure_violation | 译文含空行、非法标记或字幕控制内容，请修改正文。手动保存/导出附 errors.segmentId、field、offset、length；offset/length 为 UTF-16 偏移，0/0 表示整个分段。|
| 422 | placeholder_integrity_violation | 占位符被破坏（保存）；导出沿用 409 task_not_exportable 并附 segmentId。|
| 422 | target_encoding_unrepresentable | 译文无法用原编码表示（沿用）。|

AI 失败列表中 subtitle_structure_violation 为可重试原因，定位字段沿用 segmentId/order；规则诊断新增 subtitle_structure 规则，禁用诊断不能关闭保存、翻译和导出保护。task_busy、乐观版本及修订冲突语义保持不变。前端所有错误均经 ApiErrorMessageProvider/resx 映射。

## 前端与后续范围

共享导入组件开放两种格式及混合上传；编辑器复用现有多行、只读占位符、保存、确认、翻译、审核和下载入口。字幕不显示 txt 分段或 HTML 重提取。时间信息展示、视频预览、阅读速度、行长/行数提示、上下文增强及旧编码识别留待后续。

语法依据：[W3C WebVTT](https://www.w3.org/TR/webvtt1/) 和 [Library of Congress SRT 格式说明](https://www.loc.gov/preservation/digital/formats/fdd/fdd000569.shtml)。本文定义应用首版明确支持的子集，不承诺所有播放器扩展；既有 txt/markdown/html/epub 契约不变。
