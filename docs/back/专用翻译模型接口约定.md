# 专用翻译模型接口约定

本增量契约（2026-10-27）扩展 AI 配置、AI 翻译、AI 审核及多文件与翻译过程约定。复用全部既有路由、鉴权、分段保护与任务互斥，不增加另一套翻译接口。

## 1. 模型配置与运行快照

模型创建、全字段更新及响应新增 `translationMessageFormat`，合法值为 `general`、`hy-mt2`、`bilibili-index-translate`。缺省为 `general`（包括 PUT）；显式 null、空串、非字符串和未知值返回 `400 invalid_translation_message_format`。存量模型与运行迁移为 `general`。格式与提供商类型、地址、模型 ID 无关，不按名称推断。选项和校验共用同一格式定义。

创建翻译运行仍按既有三档选择解析模型，服务端把选中的格式保存到运行，并在创建、详情、列表回显同名只读字段；调用方不能通过运行请求覆盖格式。后续修改模型格式不影响该运行的首次请求、有限重试及持久化快照。恢复仍按既有中断语义结束旧运行，新运行重新解析当前配置，不自动续跑或修改旧运行格式。

## 2. 请求形状、语言与术语

- `general` 保持批量 JSON 协议；两个专用格式每次请求一个完整分段、仅一条当前 user 消息，不发送 system、历史、工具或 JSON 模式；非空背景按[《任务参考资料与多术语表接口约定》](任务参考资料与多术语表接口约定.md)放入对应区块；纯文本响应直接对应当前分段 ID，多行不拆分。
- 语言标签仍为 BCP 47，专用提示词使用 .NET 已知语言区域目录的完整英文语言名（简体/繁体中文显式区分）；无法映射返回 `422 unsupported_language_pair`。`sourceLanguage=null` 由模型识别，省略源语言限定，不猜测语言后选择术语。
- 专用格式按当前分段从运行创建时固定的任务所选术语表快照匹配词条：显式源语言和目标语言须精确匹配规范化标签；源语言自动识别时不注入术语。使用既有术语匹配器，忽略注册占位符，沿用 Unicode 规范化及 `caseSensitive`；不把原始标记、术语备注作为待译正文。
- 命中术语按 ID 升序确定性选取，完整映射行累计上限 1600 个 UTF-16 单元（包含换行），放不下的整条跳过，不截断词条。一个分段在有限重试中使用相同术语材料；后续分段也使用运行创建时的术语快照。无命中时不生成空术语区块。
- HY-MT2 使用默认翻译模板；有术语时增加“参考下面的翻译”映射。Index 使用源文与约束分区；术语和占位符作为硬性要求。所有格式保留占位符数量、种类、顺序、配对及嵌套；字幕沿用固定条目正文限制。

## 3. 参数与预算

专用请求固定输出上限 4096 tokens。首版保守预算为 `UTF8字节数(完整提示词) + 64消息开销 + 4096输出预留 <= 16384`；这是确定性估算口径，不是厂商 tokenizer 的准确计数或服务端上下文保证。完整提示词包含模板、语言、约束、选中术语和完整正文。超限分段记录 `translation_request_too_large`，`retryable=false`、`attempts=0`，不发 HTTP、不截断、不改变持久化分段、不切换模型或格式。较小上下文服务仍可能拒绝请求，须调整部署或另选适合的模型；预算配置界面后续再做。

HY-MT2 沿用已有 `reasoningEffort` 能力校验。Index 仅接受 null 或 `none`，两者均强制关闭思考，不要求 `supportsThinking=true`；其他合法等级返回 `422 translation_reasoning_conflict`。OpenAI 兼容请求明确发送 `chat_template_kwargs: { enable_thinking: false }`；Ollama 原生请求明确发送 `think: false`。不以 `reasoning_effort=none` 代替这两个参数，也不发送相互冲突的思考设置。不支持这些参数的服务不可静默降级：Index 请求被 HTTP 400/422 拒绝时记录 `llm_request_rejected`，不可重试（语言拒绝优先沿用语言失败码）。

## 4. 输出与失败

仅允许 HY-MT2 清理开头一层 `〖待翻译文本〗` 或 `【待翻译文本】` 包装，且原文不含该标记。其余正文不按空行、编号、引号或代码围栏切割。原文本身出现的模板标记不当作回显剥除。

空响应用 `llm_response_invalid`；完成原因 length 用 `llm_output_truncated`；新增模板区块、指令或术语映射回显用 `llm_prompt_echo`。以上均可有限重试，失败不落库。模板回显检查是确定性防线，不能保证识别所有改写后的提示词复述。占位符、漏翻和字幕正文规则继续在落库前校验，沿用既有失败码。成功分段不受其他分段失败影响。

## 5. 审核用途与界面

审核只允许 `general`。显式选择、提供商默认模型和全局默认对均须在创建时校验，专用模型返回 `422 model_not_review_capable`，不创建运行。每个审核批次及每次实际请求（含重试）前再次读取模型格式；变为专用格式时未处理分段以相同代码失败（不可重试，attempts 为已发送请求次数，首次请求前为 0），已保存审核意见保留，译文不变。不自动选择其他模型。

设置页提供三种格式并在模型列表回显；翻译选择器允许全部格式，并解释专用格式逐分段请求。Index 禁用冲突思考等级。审核选择器禁用专用模型；默认对不适用时要求明确选择通用模型，无通用模型时提供设置入口。所有提示经 resx，错误统一由 `ApiErrorMessageProvider` 映射。

| 场景 | HTTP / 分段失败 | code | retryable |
|---|---|---|---|
| 模型格式无效 | 400 | `invalid_translation_message_format` | — |
| 专用语言名无法映射 | 422 | `unsupported_language_pair` | false |
| Index 思考参数冲突 | 422 | `translation_reasoning_conflict` | — |
| 审核误用专用模型 | 422 / 分段失败 | `model_not_review_capable` | false |
| 专用请求超预算 | 分段失败 | `translation_request_too_large` | false |
| 输出截断 | 分段失败 | `llm_output_truncated` | true |
| 提示词或术语回显 | 分段失败 | `llm_prompt_echo` | true |
| Index 服务拒绝请求参数 | 分段失败 | `llm_request_rejected` | false |

## 6. 支持边界与参考

支持矩阵是两种专用格式 × OpenAI 兼容/Ollama；自动化测试捕获请求不代表任意服务均兼容。真实模型、连接器和服务实现的验证单独记录，缺少服务时保留待完成。不包含多段编号对齐、自动回退或超长分段切分；背景上下文已由 2026-10-28 增量支持；多文件与字幕仍按既有分段归属及原格式导出。

模板参考只读仓库 `C:\code\ts\ts_novel_spider` 的消息构造，以及 [HY-MT2 官方说明](https://github.com/Tencent-Hunyuan/Hy-MT2)、[Index 官方推理入口](https://github.com/bilibili/Index-Translate/blob/main/inference/llm/translate.py)。本项目保留完整分段和严格占位符校验，不采用参考项目的宽松响应拆分。
