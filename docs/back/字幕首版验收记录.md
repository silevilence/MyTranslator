# 字幕首版验收记录

日期：2026-10-26。范围：ROADMAP 八，SRT / WebVTT 后端及配套功能性前端。测试使用独立 SQLite 和本地固定响应模型，不访问真实外部 LLM；验证接口与运行编排，不评价模型翻译质量。

## 自动化验证

最终执行 `dotnet build MyTranslator.slnx --no-restore`：0 警告、0 错误。执行 `dotnet test MyTranslator.slnx --no-restore`：后端 230/230、共享层 204/204，共 434 项全部通过，无跳过。`git diff --check` 通过。

`SubtitleApiTests` 覆盖以下行为：

| 范围 | 验证内容 |
|---|---|
| 编码与字节保真 | UTF-8 有/无 BOM、SRT UTF-16 LE/BE BOM、LF/CRLF/CR、无末尾换行；原文回填导出逐字节一致；损坏编码、无 BOM UTF-16、UTF-32 拒绝 |
| 条目与标记 | 多行保持一段、空正文条目受保护、不连续序号、合法时间重叠、标签/实体、说话人/语言/段内时间标记、NOTE/STYLE/REGION 与设置 |
| 正常流程 | 导入→AI 翻译→人工多行编辑/确认→审核→同格式导出，媒体类型与扩展名正确 |
| 异常与恢复 | 反向/非法时间轴、不支持标签/实体/设置、非法空行、控制字符、箭头、新标记、占位符顺序破坏；拒绝保存且版本不变；旧数据导出重新校验；部分失败后修复与重新导出 |
| AI 响应对齐 | SRT / VTT 分别测试缺少分段、重复分段，失败批次不写入错配译文；新运行恢复后导出原文一致 |
| 多文件 | SRT + VTT + TXT + Markdown + HTML 共 9 段，文件归属与顺序正确；ZIP 成员名称、编码与字节一致；成员按持久化类型执行字幕校验 |
| 能力与下载 | 媒体类型推断、显式格式、字幕固定分段、禁止重提取；跨源响应暴露下载文件名等头部 |

既有后端全量测试同时覆盖 txt/markdown/html/epub 导入导出、翻译与审核、保存及批量确认的 `409 task_busy` 语义。共享层全量测试覆盖模型解析、服务调用、错误文案和既有编辑器逻辑。

## 真实浏览器

环境：Windows、Chromium 156（Codex 内置浏览器），Web `localhost:5000`，API `localhost:5199`。固定上传样例保存在 `tests/MyTranslator.Api.Tests/Fixtures/Subtitles/`。

1. SRT 与 WebVTT 分别完成文件选择、上传、AI 翻译（3/3）、多行正文修改、保存/确认（1/3）、AI 审核（3/3）、下载。刷新后译文、确认状态及审核意见保持一致。
2. WebVTT 编辑时插入空白行，保存显示中文结构违规提示，保留草稿与未保存标记；改为合法三行后成功保存确认。反向时间轴样例上传被明确拒绝。
3. SRT/VTT 单文件不显示 txt 分段及 HTML 重提取；混合任务中 txt 分段选择只作用于文本文件。
4. SRT + VTT + TXT 混合任务完成 7/7 翻译，下载 ZIP 包含 `sample.srt`、`sample.vtt`、`mixed.txt`。解包后时间轴及 VTT 受保护前缀与原文件一致，各成员包含对应译文。
5. 跨源下载实测文件名为 `sample.translated.srt`、`sample.translated.vtt`、`sample.translated.zip`。亮/暗主题、多行显示、占位符只读及键盘焦点已检查，详见[前端审查记录](../front/字幕支持审查记录.md)。

开发过程中遇到构建后的静态资源指纹与旧开发服务器缓存不一致，重启 Web 开发服务器后恢复；最终验证未复现该启动错误。

## 实际播放器

播放对象是浏览器下载的译文文件，未重新生成字幕。使用本地 10 秒中性背景视频。

| 播放器 | 样例 | 结果 |
|---|---|---|
| ffplay 7.1.1-full_build-www.gyan.dev（libass 字幕渲染） | `sample.translated.srt` | 中文正常、首条三行及粗体可见；3 秒画面同时显示首条与重叠字幕，持续播放按时间顺序切换 |
| Chromium 156 HTML5 video 原生 track | `sample.translated.vtt` | 原生加载 3 条 cue，保留 intro/second/last 标识及定位；首条红色样式、多行和重叠正常；段内时间标记未变为正文 |
| ffprobe 7.1.1 | 两种下载文件 | 均识别 3 个条目，起点分别 1、2.5、7 秒，时长分别 3、2.5、2 秒，与原样例一致 |

WebVTT 在 0.5、1.5、3、4.5、5.5、7.5、9.5 秒逐点检查，活动条目依次为：无、intro、intro+second、second、无、last、无。SRT 持续播放并检查首条/重叠，另固定渲染第 3 秒核验两条同时显示。没有发现丢条、串段或时间轴改写。

本机证据保存在 `.scratch/subtitle-validation/`（不入库）：`editor-light.png`、`editor-dark.png`、`webvtt-overlap.png`、`srt-overlap.png`，以及下载字幕副本、视频与播放器页面。播放器验证覆盖上述实现和样例，不代表所有播放器扩展语法均受支持。

## 整体审核与范围

结论：四项任务均满足首版验收，可标记完成；无剩余阻塞项。

按契约、数据保真、运行失败语义、互斥、前端规范及实际播放逐项审核。已修复跨源下载丢失扩展名、语言输入未即时同步，以及 WebVTT 隐式空闭标签掩盖导出后的非法正文。WebVTT 仅含空格的分隔行明确拒绝，避免与播放器产生不同条目边界。错误定位使用实际时间轴行号。

前端交付范围：格式选择/说明/展示、混合上传、多行显示、统一错误提示，以及现有翻译、编辑、确认、审核和下载闭环。后续前端事项：字幕时间信息展示、视频预览、阅读速度提示、行长/行数提示、相邻字幕只读上下文。ASS/SSA、时间轴编辑、跨格式/双语导出和旧编码识别不在首版范围。

WebVTT 标准没有可靠的必填文件内轨道用途字段，因此上传方须确认是字幕；明确 metadata/chapters 头部与其他未支持多行头部拒绝。接口不会根据正文长相推断用途。完整限制见[字幕翻译接口约定](字幕翻译接口约定.md)。
