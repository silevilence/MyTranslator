# 多文件与翻译过程接口约定

> 2026-10-28 增量：多术语表、任务绑定与背景信息、审核思考等级见[《任务参考资料与多术语表接口约定》](任务参考资料与多术语表接口约定.md)，重叠条款以增量为准。

本增量契约（2026-10-26）扩展《文件导入拆解与导出接口约定》《AI 翻译接口约定》。旧客户端与单文件任务保持兼容。

## 一个任务导入多个文件

`POST /api/tasks/imports/files` 接受 multipart 重复字段 `files`（1–20 个文件）及可选 `segmentationMode`（仅应用于其中 txt）。各文件按扩展名/媒体类型独立推断类型，支持 txt、markdown、html、epub；每文件及整批原始字节总量不超过 10 MiB。重复文件名（忽略大小写）、空名称、含路径的名称返回 `400 invalid_file_collection`；超限返回 `413 content_too_large`；解析失败沿用单文件错误码。先解析全部文件，再原子保存一个任务，失败不产生半成品任务。

多文件任务 `source.kind=files`、`fileType=bundle`、`source.fileName` 为 ZIP 包名称；原始字节与各文件重建模板持久化于 SQLite。分段顺序按上传文件顺序连续编号；`segment.sourceFileName` 为原文件名（旧单文件任务可为 null），原有 EPUB chapter 元数据保持不变。摘要额外返回 `files`（fileName、fileType、byteLength），单文件旧任务可为 null。

所有文件共享同一个任务的翻译、确认、互斥与进度。多文件任务暂不支持重新提取（canReextract=false）。导出仍走 `/api/tasks/{id}/result`，全体分段有译文后返回 `application/zip`；ZIP 内每个文件保留原文件名、格式、编码与受保护内容。不拼接原文件、不创建隐藏子任务、不接受 ZIP 导入。

## 翻译思考等级

创建翻译运行新增可选 `reasoningEffort`：null（模型默认）、`none`、`low`、`medium`、`high`、`xhigh`。非法值返回 `400 invalid_reasoning_effort`；非默认值要求所选模型 `supportsThinking=true`，否则 `422 reasoning_not_supported`；Ollama 不接受 `xhigh`。前端将这些值呈现为模型默认、关闭、低、中、高、极高。

等级存入运行并在详情/列表回显，后续批次和自动重试沿用。通过 Microsoft.Extensions.AI 的 ReasoningOptions 传给连接器；厂商/模型实际支持的档位以其接口为准，默认不发送思考参数。不发送工具，也不获取或展示内部思考文本。能力声明本身仍然是配置元数据；此独立请求字段取代 ADR-0003 旧版“翻译固定 thinking=false”的限制。

## 真实过程反馈

运行新增 `events` 数组（旧运行为空），按时间升序保留最近 30 条；每条为 `stage`、`at`（UTC）、`firstSegmentOrder`、`lastSegmentOrder`、`segmentCount`、`attempt`、`maxAttempts`、`timeoutSeconds`、可空 `code`。阶段为 `requesting`（等待模型响应）、`validating`（校验结果）、`saving`（保存译文）、`retrying`（自动重试）。每个事件在对应操作前持久化，查询仍走现有 REST 轮询。终态以运行 status 为准，事件只描述已发生的过程。

前端展示当前批次范围、尝试次数、等待时长、超时设置与最近过程记录；失败原因由稳定 code 映射。百分比仅由已处理分段计算，不随本地计时增长。等待时明确说明按批次返回与校验后更新，禁止猜测模型内部活动。不得包含密钥、提示词或厂商原始错误文本。
