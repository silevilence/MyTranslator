# 术语接口约定

本文定义术语表管理与术语对齐检查对 Web 端、桌面端和第三方系统公开的 REST 接口。接口覆盖术语条目的增删改查、模糊匹配查询，以及按任务提取修订检查译文是否使用规定术语并返回未对齐分段。

鉴权、基础地址和通用 Problem Details 格式以[《鉴权与基础接口约定》](鉴权与基础接口约定.md)为准。本文所有接口均要求 Bearer Token。任务、分段、提取修订、占位符和只读标记表的字段语义以[《文件导入拆解与导出接口约定》](文件导入拆解与导出接口约定.md)及 [ADR-0002](../adr/0002-标记提取模型.md)为准。

## 1. 范围与接口原则

- 术语条目规定一个源语言术语在目标语言中的期望术语；Web、桌面端和第三方系统使用完全相同的接口。
- 每个术语条目都属于一个 `sourceLanguage` + `targetLanguage` 语言对。术语查询可做模糊匹配；术语对齐检查只做确定性包含匹配，不把模糊相似度用于判定未对齐。
- 所有已保存术语均立即生效。v1 不提供启用/停用状态；不再使用的术语应删除。
- 更新和删除采用 `version` 乐观并发控制，调用方不得用最后写入覆盖其他调用方已经保存的修改。
- 术语对齐检查是只读的同步操作：检查任务当前提取修订中已有译文的分段，返回本次检查快照中的未对齐项，不持久化检查运行或修改分段。
- 本文只定义术语资源和独立对齐检查接口；后续硬性规则检查可复用同一匹配器并持久化规则违规，但不得改变本文的术语字段和匹配语义。

## 2. 通用约定

### 2.1 标识、时间与 JSON

- `termId`、`taskId`、`segmentId` 均为 UUID 字符串。
- 时间使用 UTC ISO 8601，例如 `2026-08-18T08:30:00Z`。
- JSON 字段使用 `camelCase`，请求和响应使用 UTF-8。
- 枚举值使用本文列出的英文小写字符串；调用方必须容忍未来增加未知枚举值。
- `version` 是从 `1` 开始的正整数；术语创建时为 `1`，每次成功更新后递增一次。

### 2.2 术语文本与语言标签

- `sourceTerm` 和 `targetTerm` 均必填，去除首尾空白后长度为 `1..500` 个 Unicode 标量值；服务端以 Unicode NFC 形式保存，保留大小写和内部空白。
- `sourceLanguage` 和 `targetLanguage` 均必填，使用 BCP 47 语言标签，例如 `en`、`zh-CN`、`pt-BR`；服务端规范化大小写后保存和回显。
- `notes` 为可选说明；缺省、`null` 或纯空白统一保存为 `null`，非空时去除首尾空白，最大 `2,000` 个 Unicode 标量值。
- `caseSensitive` 控制对齐检查时源术语和期望术语是否区分大小写；创建时缺省为 `false`。
- 同一语言对中，`sourceTerm` 经 NFC、首尾去空白和不区分大小写比较后必须唯一。唯一性比较不折叠内部空白，且始终不区分大小写，不受 `caseSensitive` 影响。已有同源术语应通过更新修改其期望术语，不得创建第二条相互竞争的规定译法。

### 2.3 游标分页

术语列表使用游标分页：

```http
GET /api/terms?query={query}&sourceLanguage={sourceLanguage}&targetLanguage={targetLanguage}&limit=100&cursor={opaqueCursor}
```

- `limit` 默认 `100`，范围 `1..200`。
- `cursor` 是不透明字符串，调用方不得解析或构造。
- `nextCursor = null` 表示末页。
- 游标绑定产生它的 `query`、`sourceLanguage` 和 `targetLanguage`；改变任一查询条件后，调用方必须丢弃旧游标并从第一页加载。
- 无模糊查询时，游标记录最后一项的 `updatedAt` + `id` 键集位置；有模糊查询时记录 `matchScore` + `updatedAt` + `id` 键集位置，并沿用 §2.4 的排序方向。
- 游标不可解析、不属于术语列表或与当前查询条件不一致时返回 `400 invalid_cursor`。
- 创建、更新或删除术语后，前端应从第一页刷新，不继续使用修改前的游标。
- 分页期间其他调用方更新术语可能使条目重新排序，造成后续页轻微重复或跳过；列表分页不提供跨请求快照。要求最新一致视图的调用方应从第一页重新加载并按 `id` 去重。

### 2.4 模糊查询规则

`query` 缺省、空字符串或纯空白时不做模糊筛选。非空查询去除首尾空白后最大为 `500` 个 Unicode 标量值，同时匹配 `sourceTerm` 和 `targetTerm`，不搜索 `notes`：

1. 查询和候选文本均执行 NFC、首尾去空白、连续空白折叠和不区分大小写规范化；该搜索行为不受术语的 `caseSensitive` 影响。
2. 完全相等的 `matchScore` 为 `1.0`。
3. 候选包含完整查询文本时，`matchScore` 为 `0.9`。
4. 查询文本包含完整候选时，`matchScore` 为 `0.8`，使嵌在较长搜索语句中的完整术语仍可返回。
5. 其他候选使用规范化 Levenshtein 相似度 `1 - distance / max(queryLength, candidateLength)`；分数小于 `0.6` 的候选不返回。
6. 源术语和目标术语都匹配时取较高分；同分时 `matchedField` 为 `source`。
7. `matchScore` 保留四位小数。它只用于同一次查询内排序和展示，不得用于术语对齐判定。

有 `query` 时按 `matchScore` 降序、`updatedAt` 降序、`id` 升序返回；无 `query` 时按 `updatedAt` 降序、`id` 升序返回。

### 2.5 乐观并发

- 更新请求体必须携带调用方最后读取到的 `version`；删除请求必须通过查询参数携带该版本。
- 请求版本与数据库当前版本不一致时返回 `409 term_version_conflict`，响应的 `errors` 含 `requestedVersion` 和 `currentVersion`。
- 发生版本冲突后，前端必须重新读取术语并由用户决定是否重新提交，不得自动覆盖。
- 术语已经被删除时返回 `404 term_not_found`，不再返回版本冲突。

## 3. 术语数据模型

术语资源形状如下：

```json
{
  "id": "01f42ee7-2f9b-45e8-b753-a070253a230d",
  "sourceTerm": "translation memory",
  "targetTerm": "翻译记忆库",
  "sourceLanguage": "en",
  "targetLanguage": "zh-CN",
  "notes": "首次出现时可附英文缩写 TM。",
  "caseSensitive": false,
  "version": 1,
  "createdAt": "2026-08-18T08:30:00Z",
  "updatedAt": "2026-08-18T08:30:00Z"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | UUID | 响应 | 术语 ID |
| `sourceTerm` | string | 是 | 源术语，约束见 §2.2 |
| `targetTerm` | string | 是 | 规定使用的期望术语，约束见 §2.2 |
| `sourceLanguage` | string | 是 | 源语言 BCP 47 标签 |
| `targetLanguage` | string | 是 | 目标语言 BCP 47 标签 |
| `notes` | string/null | 否 | 人工说明；无说明时为 `null` |
| `caseSensitive` | boolean | 否 | 对齐检查是否区分大小写；默认 `false` |
| `version` | integer | 响应/更新/删除 | 乐观并发版本 |
| `createdAt` | string | 响应 | 创建时间，更新时不变 |
| `updatedAt` | string | 响应 | 最近一次成功写入时间 |

## 4. 创建术语

### POST /api/terms

请求体：

```json
{
  "sourceTerm": "translation memory",
  "targetTerm": "翻译记忆库",
  "sourceLanguage": "en",
  "targetLanguage": "zh-CN",
  "caseSensitive": false
}
```

示例：

```bash
curl -X POST http://localhost:5199/api/terms \
  -H "Authorization: Bearer sk-dev-00000000000000000000000000000000" \
  -H "Content-Type: application/json" \
  -d '{"sourceTerm":"translation memory","targetTerm":"翻译记忆库","sourceLanguage":"en","targetLanguage":"zh-CN","caseSensitive":false}'
```

成功返回 `201 Created`，设置资源地址并返回完整术语：

```http
Location: /api/terms/01f42ee7-2f9b-45e8-b753-a070253a230d
```

```json
{
  "id": "01f42ee7-2f9b-45e8-b753-a070253a230d",
  "sourceTerm": "translation memory",
  "targetTerm": "翻译记忆库",
  "sourceLanguage": "en",
  "targetLanguage": "zh-CN",
  "notes": null,
  "caseSensitive": false,
  "version": 1,
  "createdAt": "2026-08-18T08:30:00Z",
  "updatedAt": "2026-08-18T08:30:00Z"
}
```

同一语言对已有相同规范化 `sourceTerm` 时返回 `409 term_conflict`；`errors.conflictingTermId` 指向已有术语，调用方可跳转编辑该资源。

## 5. 列出与模糊查询术语

### GET /api/terms

查询参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `query` | string | 否 | 同时模糊匹配源术语和目标术语，最大 500 个 Unicode 标量值；规则见 §2.4 |
| `sourceLanguage` | string | 否 | 精确筛选规范化后的源语言标签 |
| `targetLanguage` | string | 否 | 精确筛选规范化后的目标语言标签 |
| `limit` | integer | 否 | 默认 `100`，范围 `1..200` |
| `cursor` | string | 否 | 上一页返回的不透明游标 |

示例：

```bash
curl "http://localhost:5199/api/terms?query=translatoin&sourceLanguage=en&targetLanguage=zh-CN&limit=20" \
  -H "Authorization: Bearer sk-dev-00000000000000000000000000000000"
```

成功返回 `200 OK`：

```json
{
  "items": [
    {
      "id": "01f42ee7-2f9b-45e8-b753-a070253a230d",
      "sourceTerm": "translation",
      "targetTerm": "翻译",
      "sourceLanguage": "en",
      "targetLanguage": "zh-CN",
      "notes": null,
      "caseSensitive": false,
      "version": 3,
      "createdAt": "2026-08-18T08:30:00Z",
      "updatedAt": "2026-08-18T09:05:00Z",
      "matchScore": 0.8182,
      "matchedField": "source"
    }
  ],
  "nextCursor": null
}
```

列表项在 §3 完整术语形状上增加：

| 字段 | 类型 | 说明 |
|---|---|---|
| `matchScore` | number/null | 有非空 `query` 时为 `0..1`；无查询时为 `null` |
| `matchedField` | string/null | `source` / `target`；无查询时为 `null` |

没有匹配项时返回 `200 OK`、空 `items` 和 `nextCursor = null`。前端必须把搜索词和语言筛选提交给后端，不在当前页结果上自行实现第二套模糊匹配。

## 6. 读取单个术语

### GET /api/terms/{termId}

示例：

```bash
curl http://localhost:5199/api/terms/01f42ee7-2f9b-45e8-b753-a070253a230d \
  -H "Authorization: Bearer sk-dev-00000000000000000000000000000000"
```

成功返回 `200 OK` 和 §3 的完整术语形状，不包含列表查询专用的 `matchScore`、`matchedField`。术语不存在时返回 `404 term_not_found`。

## 7. 更新术语

### PUT /api/terms/{termId}

更新采用完整替换。`sourceTerm`、`targetTerm`、两个语言字段、`caseSensitive` 和 `version` 必须提交；`notes` 缺省时按 `null` 处理。

请求体：

```json
{
  "sourceTerm": "translation memory",
  "targetTerm": "翻译记忆库",
  "sourceLanguage": "en",
  "targetLanguage": "zh-CN",
  "notes": "固定使用完整名称，不简写为记忆库。",
  "caseSensitive": false,
  "version": 1
}
```

示例：

```bash
curl -X PUT http://localhost:5199/api/terms/01f42ee7-2f9b-45e8-b753-a070253a230d \
  -H "Authorization: Bearer sk-dev-00000000000000000000000000000000" \
  -H "Content-Type: application/json" \
  -d '{"sourceTerm":"translation memory","targetTerm":"翻译记忆库","sourceLanguage":"en","targetLanguage":"zh-CN","notes":"固定使用完整名称，不简写为记忆库。","caseSensitive":false,"version":1}'
```

成功返回 `200 OK` 和更新后的完整术语；`version` 递增一次，`updatedAt` 更新，`createdAt` 不变。即使提交内容与当前内容相同，只要版本匹配，该请求仍视为一次成功更新并递增版本。

更新后与同语言对的另一术语形成源术语冲突时返回 `409 term_conflict`；路径资源不存在返回 `404 term_not_found`；版本过期返回 `409 term_version_conflict`。

## 8. 删除术语

### DELETE /api/terms/{termId}?version={version}

示例：

```bash
curl -X DELETE "http://localhost:5199/api/terms/01f42ee7-2f9b-45e8-b753-a070253a230d?version=3" \
  -H "Authorization: Bearer sk-dev-00000000000000000000000000000000"
```

- 版本匹配且删除成功时返回 `204 No Content`。
- 删除立即影响之后创建的查询与对齐检查，但不会修改已有任务的源文、译文或确认状态。
- 重复删除返回 `404 term_not_found`；版本过期返回 `409 term_version_conflict`。
- 前端删除前必须遵守《交互规范》的危险操作确认要求；后端不接受无 `version` 的无条件删除。

## 9. 检查任务的术语对齐

### POST /api/tasks/{taskId}/term-alignment-checks

该接口同步检查指定任务当前提取修订中已有译文的分段。请求语言对决定使用哪些术语，服务端不从最新翻译运行或界面本地状态推断。本端点不创建可寻址资源，不返回 `201 Created` 或 `Location`；检查完成后直接以 `200 OK` 返回结果。

请求体：

```json
{
  "extractionRevision": 1,
  "sourceLanguage": "en",
  "targetLanguage": "zh-CN"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `extractionRevision` | integer | 是 | 调用方当前看到的提取修订，必须大于等于 `1` |
| `sourceLanguage` | string | 是 | 用于选择术语的源语言 BCP 47 标签 |
| `targetLanguage` | string | 是 | 用于选择术语的目标语言 BCP 47 标签 |

示例：

```bash
curl -X POST http://localhost:5199/api/tasks/4d898d78-1f24-47e9-8e30-adcee716c13d/term-alignment-checks \
  -H "Authorization: Bearer sk-dev-00000000000000000000000000000000" \
  -H "Content-Type: application/json" \
  -d '{"extractionRevision":1,"sourceLanguage":"en","targetLanguage":"zh-CN"}'
```

成功返回 `200 OK`：

```json
{
  "taskId": "4d898d78-1f24-47e9-8e30-adcee716c13d",
  "extractionRevision": 1,
  "sourceLanguage": "en",
  "targetLanguage": "zh-CN",
  "summary": {
    "totalSegments": 42,
    "checkedSegments": 40,
    "skippedUntranslatedSegments": 2,
    "languagePairTermCount": 18,
    "matchedSegments": 9,
    "alignedSegments": 8,
    "unalignedSegments": 1
  },
  "items": [
    {
      "segmentId": "7d59abcf-eaf4-42d3-b1fe-f78bf08ca72b",
      "segmentOrder": 17,
      "segmentVersion": 4,
      "misalignments": [
        {
          "termId": "01f42ee7-2f9b-45e8-b753-a070253a230d",
          "sourceTerm": "translation memory",
          "expectedTargetTerm": "翻译记忆库",
          "caseSensitive": false,
          "sourceOccurrences": 1,
          "targetOccurrences": 0
        }
      ]
    }
  ],
  "checkedAt": "2026-08-18T09:15:00Z"
}
```

### 9.1 响应字段与计数

| 字段 | 约束 |
|---|---|
| `checkedSegments` | `targetText` 非 `null` 且非空白、实际参与检查的分段数 |
| `skippedUntranslatedSegments` | `targetText = null` 的未翻译分段数；不产生未对齐项 |
| `languagePairTermCount` | 本次语言对快照中的术语总数，与分段是否命中无关；可用于展示该语言对是否配置术语 |
| `matchedSegments` | `sourceText` 至少命中一个适用源术语的分段数 |
| `alignedSegments` | 命中过源术语且所有命中术语均在译文中出现期望术语的分段数 |
| `unalignedSegments` | 至少有一个 `misalignments` 项的分段数，等于 `items` 数量 |
| `segmentVersion` | 检查时的分段乐观并发版本；前端可判断检查结果是否已因编辑而陈旧 |
| `misalignments` | 只包含源文已命中、译文中期望术语出现次数为 `0` 的术语，按 `sourceTerm`、`termId` 排序 |
| `sourceOccurrences` | 规范化源文中源术语的不重叠出现次数，至少为 `1` |
| `targetOccurrences` | 未对齐项固定为 `0`；保留该字段便于后续兼容完整对齐详情 |

`matchedSegments = alignedSegments + unalignedSegments`。没有适用术语、没有已翻译分段或全部通过时仍返回 `200 OK`；`items` 为空，不把“未配置术语”视为系统错误。

### 9.2 确定性匹配规则

对每个分段和适用术语执行以下规则：

1. 只使用与请求 `sourceLanguage`、`targetLanguage` 完全匹配的术语。
2. 根据分段只读 `markupTable` 识别 `sourceText`、`targetText` 中真实的 `<xN>`、`</xN>`、`<xN/>` 占位符引用，并将每个引用替换为一个空格；不得仅用正则删除所有形似占位符的字面文本。
   占位符边界因此视同空白，允许跨标记匹配；例如 `Hello <x1>World</x1>` 可命中术语 `Hello World`。
3. 文本与术语均执行 Unicode NFC、首尾去空白和连续空白折叠。
4. `caseSensitive = false` 时再执行不区分大小写比较；为 `true` 时保留原大小写。
5. 使用规范化后的连续子串包含匹配，不做模糊匹配、词干还原、分词或同义词扩展。
6. 源术语在 `sourceText` 中至少出现一次且期望术语在 `targetText` 中至少出现一次，即视为该术语已对齐；不要求源、目标出现次数相等。
7. 一个分段命中多个源术语时逐条判断；任一术语未对齐，该分段即进入 `items`，并列出全部未对齐项。

因此，模糊查询可帮助用户找到术语，但不会使拼写相近的源文触发未对齐结果。调用方不得在前端重新实现或放宽上述判定。

### 9.3 快照、一致性与边界行为

- 后端在同一只读数据库快照中读取当前提取修订、术语集合和分段；响应描述该快照，不持久化检查结果。
- 请求 `extractionRevision` 与任务当前修订不一致时返回 `409 extraction_revision_changed`，`errors` 含请求值和当前值。
- 检查不修改任务状态、分段 `targetText`、确认状态或 `version`，不加入会产生 `409 task_busy` 的任务写操作互斥，也不阻塞翻译运行；活动翻译期间调用可能只看到已经提交的译文，调用方可在进度变化后再次检查。
- `targetText = null` 表示未翻译并跳过。按照《文件导入拆解与导出接口约定》§6，非 `null` 时必须至少含一个非空白字符；违反时整次检查返回 `422 invalid_segment_state`，不得把它悄悄当作未对齐或未翻译。`errors` 返回 `invalidSegmentCount`、按分段顺序定位的 `firstInvalidSegmentId` 和 `firstInvalidSegmentOrder`，供调用方读取并修复首个异常分段。
- 重新提取后旧分段 ID 不再有效；调用方收到 `409 extraction_revision_changed` 后必须重新读取任务和分段，再发起检查。
- `items` 按 `segmentOrder` 升序返回；本同步接口返回本次检查的全部未对齐分段，不分页、不截断，也不返回 `truncated` 标志。v1 以单任务 `10,000` 个分段作为容量验证基线，但这不是硬性任务上限；调用方不得假设响应较小。
- 本接口不承诺固定完成时限，也不在请求断开后转为后台运行；实现应在一次 HTTP 请求生命周期内完成快照读取、检查和响应。调用方不得因等待时间较长而并发提交同一检查。

## 10. 错误码

请求失败统一返回 `application/problem+json`。本文沿用基础文档并增加稳定的 `code`；字段级信息放在 `errors` 扩展中。前端按 `code` 映射文案，`title` 和 `detail` 仅用于诊断。

版本冲突示例：

```json
{
  "type": "urn:mytranslator:problem:term-version-conflict",
  "title": "The term has changed since it was read.",
  "status": 409,
  "code": "term_version_conflict",
  "instance": "/api/terms/01f42ee7-2f9b-45e8-b753-a070253a230d",
  "errors": {
    "requestedVersion": 2,
    "currentVersion": 3
  }
}
```

| HTTP | `code` | 场景 |
|---|---|---|
| 400 | `invalid_source_term` | `sourceTerm` 缺失、纯空白或超过 500 个 Unicode 标量值 |
| 400 | `invalid_target_term` | `targetTerm` 缺失、纯空白或超过 500 个 Unicode 标量值 |
| 400 | `invalid_term_notes` | `notes` 超过 2,000 个 Unicode 标量值 |
| 400 | `invalid_term_query` | 非空 `query` 超过 500 个 Unicode 标量值 |
| 400 | `invalid_language_tag` | 术语或检查请求中的语言字段缺失或不是合法 BCP 47 标签 |
| 400 | `invalid_term_version` | 更新/删除的 `version` 缺失、类型错误或小于 `1` |
| 400 | `invalid_extraction_revision` | 对齐检查的 `extractionRevision` 缺失、类型错误或小于 `1` |
| 400 | `invalid_cursor` | 游标不可解析、不属于术语列表或与当前查询条件不一致 |
| 400 | `invalid_pagination` | `limit` 不在 `1..200` 范围内 |
| 404 | `term_not_found` | 术语不存在 |
| 404 | `task_not_found` | 对齐检查指定的任务不存在 |
| 409 | `term_conflict` | 同一语言对已有相同规范化源术语；`errors` 含 `conflictingTermId` |
| 409 | `term_version_conflict` | 更新或删除使用了过期版本 |
| 409 | `extraction_revision_changed` | 对齐检查请求的提取修订不是任务当前修订 |
| 422 | `invalid_segment_state` | 已有分段违反 `targetText = null` 表示未翻译、非 `null` 必须包含非空白字符的公共契约；`errors` 含 `invalidSegmentCount`、`firstInvalidSegmentId`、`firstInvalidSegmentOrder` |

Token 问题仍按《鉴权与基础接口约定》返回 `401`；已认证无权时返回 `403`；未处理的服务端错误返回 `500`，且不得暴露数据库语句、主机路径或内部堆栈。

## 11. 前端调用流程

### 11.1 术语表管理界面

1. 进入 `/terms` 后调用 `GET /api/terms` 加载第一页；列表加载使用骨架屏，页级失败显示带重试动作的 ErrorBanner。
2. 搜索词或语言筛选变化后取消或忽略旧请求，丢弃旧游标，并把条件提交给后端；不得只筛选当前已加载页。
3. 新增成功后使用 `201` 响应中的完整术语更新界面，随后可从第一页刷新；编辑时提交当前 `version`，使用 `200` 响应替换本地对象。
4. 删除前显示 ConfirmDialog；确认后用当前 `version` 调用 DELETE。提交期间按钮进入 loading 并禁用，防止重复提交。
5. 创建、更新、删除成功后按《交互规范》显示 Snackbar。刷新页面后始终以 API 数据为准，不依赖仅存在于内存的本地副本。
6. `term_version_conflict` 时重新读取该术语并提示内容已变化；不得自动重试覆盖。`term_conflict` 时可根据 `conflictingTermId` 引导用户编辑已有术语。
7. 所有失败文案由稳定 `code` 映射生成；任意 `401` 继续执行全局清理 Token 并跳转登录的既有流程。

### 11.2 术语对齐结果使用

1. 调用方先读取任务摘要取得当前 `extractionRevision`，并明确提交本次检查的源语言与目标语言。Web/桌面端可通过 `GET /api/tasks/{taskId}/translation-runs` 读取最新翻译运行，并在其 `sourceLanguage`、`targetLanguage` 同时非空时作为表单默认值；没有运行或最新运行的 `sourceLanguage = null`（由 LLM 自动识别）时必须由用户手动选择。用户手动选择始终可以覆盖默认值。
2. 提交期间禁用检查动作；收到结果后按 `segmentId` 关联既有分段，并用 `expectedTargetTerm` 展示期望术语。
3. 若分段当前 `version` 已不同于结果中的 `segmentVersion`，结果视为陈旧，应重新检查，不继续显示为当前结论。
4. `409 extraction_revision_changed` 时丢弃结果与旧分段缓存，从任务和分段第一页重新加载。

术语表管理界面只管理带语言对的术语资源，不负责推断任务语言对；上述默认值与手动选择流程属于翻译编辑器增强阶段的对齐检查入口。

## 12. 与既有及后续契约的关系

| 相关文档/任务 | 本文约束 |
|---|---|
| 鉴权与基础接口约定 | 沿用 Bearer Token、`401`/`403` 语义和 Problem Details 格式 |
| 文件导入拆解与导出 | 复用 `taskId`、`segmentId`、`extractionRevision`、`targetText = null`、分段 `version` 和只读 `markupTable`；不改变分段或受保护块语义 |
| ADR-0002 | 对齐检查必须根据标记表识别并忽略真实占位符；字面 `<xN>` 文本仍是可译文本 |
| AI 翻译 | 后端可按运行语言对和源文查询相关术语并注入 LLM 上下文，无需改变既有翻译运行请求、进度或分段写入语义 |
| 硬性规则检查 | 后续规则引擎应复用 §9.2 的确定性匹配器；若将未对齐持久化为规则违规，由规则检查接口定义其生命周期，不改变本文同步响应 |
| 翻译编辑器增强 | 可按 `segmentId` 展示未对齐提示和 `expectedTargetTerm`；分段编辑保存仍以未来任务接口约定为准 |
| TM 与历史对比 | TM 可调用术语模糊查询作为参考，但不得把 `matchScore` 当作对齐结论或改变术语唯一性规则 |

本文不定义人工译文保存、规则违规持久化、TM 相似度或 AI 审核意见。后续文档只能新增资源或可选字段，不得改变本文既有术语字段语义、模糊查询与确定性对齐的边界、乐观并发要求、分段字段语义、占位符语法及标记表只读性。
