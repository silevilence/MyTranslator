# 任务管理接口约定

所有端和第三方使用同一 Bearer Token REST API。文件与分段公共契约见《文件导入拆解与导出接口约定》，翻译/审核运行见对应文档；本约定补全人工编辑、确认、进度和结果链路。

## 保存译文

`PUT /api/tasks/{taskId}/segments/{segmentId}`：

```json
{"extractionRevision":1,"version":1,"targetText":"你好","confirmationStatus":"confirmed","sourceLanguage":"en","targetLanguage":"zh-CN"}
```

200 返回最新完整分段（形状同 GET segments，含标记表、章归属、审核意见）。`extractionRevision`、`version` 必须为正整数；`targetText` 必须显式提供，可为 null；`confirmationStatus` 必须为 pending/translated/confirmed。
拒绝未知字段，特别是只读 sourceText/markupTable/chapter；不能修改来源结构或受保护块。文本不裁剪，空白统一保存为 null；null 必须搭配 pending，非空必须搭配 translated 或 confirmed。清空译文前客户端必须确认后果。

服务端在同一任务锁和数据库事务中校验修订、版本、运行互斥及占位符，再保存译文、确认状态并递增 version。完全相同的保存不递增版本。冲突时不覆盖他人内容，客户端保留本地草稿并让用户刷新/重新编辑。
只保存可译文本及其合法 `<xN>` 引用；缺失/改写/新增/错误嵌套/顺序变化均 422 拒绝，标记表不被替换。仅含占位符而无实际译文同样拒绝。
人工保存不清空 AI 审核意见；重审和重提取的生命周期仍以审核契约为准。

确认或修改已确认译文时，必须明确语言对（BCP 47，规范化后不能相同），并在同一事务自动沉淀 TM；写入失败整体回滚。取消确认不删除历史 TM。未修改的已确认分段幂等保存不再要求语言对、不重复沉淀。TM 单条文本上限仍为 20,000 Unicode 标量；超限可普通保存，确认会明确报错且不丢草稿。

## 批量确认

`POST /api/tasks/{taskId}/segment-confirmations`：

```json
{"extractionRevision":1,"confirmed":true,"items":[{"segmentId":"00000000-0000-0000-0000-000000000001","version":2}],"sourceLanguage":"en","targetLanguage":"zh-CN"}
```

items 为 1..200 个不重复分段 ID/版本；confirmed 必须显式提供。true 确认已有合法译文；false 取消确认（无译文保持 pending）。不接收本地草稿，前端须先保存当前草稿。200 返回按请求顺序排列的最新分段数组。
任一项不存在、版本冲突、无译文或 TM 写入失败，整个批次回滚。超过 200 项前端须分批并明确每批结果，不能伪装跨请求原子性。

## 生命周期与进度

任务列表和任务详情均提供 `progress`：`completedSegments`、`totalSegments`、`confirmedSegments`、`percent`、`confirmedPercent`。
完成计数仍是 targetText 非 null 的分段数；人工确认单独计数，不改变完成数。百分比保留一位小数；零分段任务为 100%，受保护块不计入分段。
翻译排队/处理中为 processing，成功全部有译文为 completed，翻译失败为 failed。人工补齐全部译文转 completed；清空后为 created（已有 failed 保留失败状态直到补齐或重新运行）。人工编辑是同步操作，不制造 processing 中间态。审核不改变公共状态。
活动翻译/审核（含 queued）期间保存和批量确认均 409 task_busy。

## 第三方端到端顺序

1. POST `/api/tasks/imports/file`（multipart file）或 `/api/tasks/imports/url` 创建任务，保存 taskId/extractionRevision。
2. POST `/api/tasks/{id}/translation-runs`，提交 extractionRevision、sourceLanguage、targetLanguage，可选 providerId/modelId。需已通过 AI 配置 API 配置提供商。按 Location 和 Retry-After 查询运行至终态。
3. GET `/api/tasks/{id}/segments`，按 nextCursor 遍历公共分段。
4. 用最新 version 调用本页 PUT 编辑/确认；需要时调用批量确认。版本变化后重新获取 TM/术语/规则诊断。
5. GET `/api/tasks/{id}` 或 GET `/api/tasks` 查询任务状态及完成/确认进度。
6. GET `/api/tasks/{id}/result` 下载还原文件，与现有 `/export` 同行为、Content-Type 和 Content-Disposition。未译完/占位符损坏返回 409 task_not_exportable；活动任务返回 409 task_busy。

## 错误与前端文案

| HTTP | code | 文案 |
|---|---|---|
| 400 | invalid_extraction_revision | 提取修订无效，请刷新任务。|
| 400 | invalid_segment_version | 分段版本无效，请刷新分段。|
| 400 | invalid_confirmation_status | 译文与确认状态不一致。|
| 400 | invalid_segment_batch | 请选择 1 至 200 个不重复分段。|
| 400 | invalid_language_tag | 请输入有效且不同的源语言与目标语言。|
| 400 | invalid_tm_target_text | TM 文本超过允许长度，无法确认。|
| 404 | task_not_found / segment_not_found | 任务不存在。/ 分段不存在，请刷新任务。|
| 409 | extraction_revision_changed | 分段已重新提取，请刷新任务。|
| 409 | segment_version_conflict | 分段已被修改，请保留草稿并刷新。|
| 409 | task_busy | 任务正在翻译或审核，请稍后重试。|
| 422 | placeholder_integrity_violation | 占位符被破坏，请恢复标记后保存。|
| 422 | missing_translation | 译文缺失。|
| 422 | tm_language_pair_required | 确认前请填写源语言与目标语言。|

未知/缺失字段等 JSON 绑定错误为 400 `invalid_request_body`（“请求内容无效，请检查输入。”）；鉴权失效走全局 401 清 Token 并登录。冲突响应 errors 可带 segmentId/currentVersion；违规 errors 带 segmentId/field/offset/length。
