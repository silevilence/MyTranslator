# ADR-0003：AI 提供商与模型二级配置 — 注册表 + 默认对

- 状态：已接受（2026-08-14）
- 范围：后端 AI 翻译配置与执行层、`docs/back` AI 翻译接口约定、前端 AI 翻译操作面板与配置界面
- 相关：[CONTEXT.md](../../CONTEXT.md)「AI 服务」、[ROADMAP.md](../../ROADMAP.md)「后端：AI 提供商与模型配置管理 API」「前端：AI 模型配置界面」、[AI 翻译接口约定](../back/AI%20翻译接口约定.md)

## 背景

现有 LLM 配置是**单一扁平对**：`TranslationOptions`（Provider/BaseUrl/ApiKey/Model/BatchSize/RequestTimeout/MaxAttempts）经 appsettings/环境变量注入，契约 §3 明确不提供远程配置 API。需求演进：① 配置多个提供商/模型用于对比测试（现有方式每次手工改环境变量）；② 为后续 Agent 功能铺路（Agent 可能按任务选不同模型）；③ 能力标注（思考/工具使用/流式）。两条实现路线：

- **单一活动对**：任一时刻一个生效「提供商+模型」，配置按二级组织但请求不可选择。
- **多提供商注册表**：配置多个提供商（各含多模型），翻译运行请求可显式选择，缺省走默认对。

## 决策

1. **二级配置模型（注册表）**：`AI 提供商（Provider）` = 连接器 kind + BaseUrl + ApiKey + enabled；`AI 模型（Model）` 挂于提供商下 = 厂商模型 ID + 展示名 + 能力元数据。`Provider.isDefault` 全局唯一、`Model.isDefault` 提供商内唯一，二者合成**默认对**。
2. **翻译运行三档解析**：请求可选 `providerId`/`modelId`——都缺省 → 默认对；只传 `providerId` → 该提供商默认模型；都传 → 精确指定。运行资源回显所选提供商/模型，失败重试沿用同一选择。
3. **能力作为模型元数据**：`supportsThinking`/`supportsToolUse`/`supportsStreaming` 仅作声明与界面展示，**不进入翻译运行请求**；请求级能力开关随 Agent/编辑器任务加入，翻译运行固定 thinking=false、tools 空、非流式。
4. **执行层采用 Microsoft.Extensions.AI**：`IChatClient` 按 kind 由工厂构造（v1 支持 `openai` 与 `ollama` 连接器；`openai` 可配 BaseUrl 覆盖 OpenAI/DeepSeek/Ollama 兼容端点，anthropic/azure 后续同工厂模式）。**移除自研 `ITranslationProvider`**：翻译处理器直接消费 `IChatClient`，批量提示词、JSON 解析与超时/鉴权错误码映射迁入处理器。
5. **配置存 SQLite**（新增 Providers/Models 表），配置管理 API 为唯一写入途径，appsettings 的 Translation 节退役。ApiKey **明文存储**（个人本地工具，DB 本就存文档内容），API 响应一律掩码（如 `sk-***abcd`）且不写日志。`IChatClient` 按批次从当前 DB 状态构造，不做缓存（避免失效问题）。
6. **新错误码**：404 `provider_not_found`、422 `model_not_found`；503 `llm_not_configured` 语义收窄为「**选中的**提供商/模型未配置完整」（无默认对也算）。

## 理由

- 多提供商注册表直接满足对比测试需求，且 Agent 后续可按任务选模型，不必再改配置形态。
- Microsoft.Extensions.AI 为微软官方 .NET 抽象，连接器覆盖面广（OpenAI 兼容端点一个 kind 通吃），避免自研多连接器；Agent 期 `AgentFramework` 与其同源，配置层可直接复用。
- 能力作元数据保持翻译运行契约最小——批量翻译用不到流式/工具，请求参数不进无用字段。
- 按批次构造客户端免除缓存失效设计；个人工具明文密钥+响应掩码是泄露面与复杂度的务实平衡。

## 后果

- 正向：配置可经 UI 管理、多模型可切换对比；Agent 与编辑器后续直接消费同一配置层与 `IChatClient` 构造路径。
- 反向：翻译运行请求契约变更（新增 `providerId`/`modelId`、回显字段、新错误码）；处理器承担提示词/解析/错误映射而变胖；契约 §3/§4/§10.1 需重写；执行层依赖 M.E.AI 版本演进。
- 配置与密钥语义变化：密钥从环境变量移入 DB，Docker 部署的密钥注入方式需随之调整（后续容器化任务）。

## 替代方案

- **单一扁平活动对**：改动最小、契约不变，但无法并行配置多模型对比测试，Agent 期仍需重构配置形态（拒绝）。
- **保留 `ITranslationProvider` 批接口、M.E.AI 作内部传输**：处理器零改动，但自研抽象与 M.E.AI 重复承担「提示词/解析/传输」职责，层级冗余（未采纳，处理器直接消费 `IChatClient`）。
- **ApiKey 加密存储（.NET DataProtection）**：泄露面更小，但引入平台绑定（Linux Docker 密钥环），个人工具收益有限（v1 明文+掩码，后续按需加密）。
