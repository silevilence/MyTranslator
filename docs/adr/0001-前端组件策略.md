# ADR-0001：前端组件策略 — 混合：MudBlazor + 自研领域组件

- 状态：已接受（2026-08-12）
- 范围：前端（Web WASM / MAUI Hybrid / RCL 共享组件库）
- 相关：[docs/front](../front/README.md)、[CONTEXT.md](../../CONTEXT.md)

## 背景

前端需同时服务网页端与桌面端，共用 Razor Class Library 组件库。UI 以翻译编辑器为核心（分段表格、详情编辑、差异对比、进度看板）。ROADMAP 要求搭建"基础组件（按钮/表格/弹窗等）"。AGENTS.md 约定：前端交互统一 Blazor 组件 + C#（禁 npm），NuGet 依赖需评估活跃度与来源可信度。

## 决策

1. **通用组件使用 MudBlazor**（版本锁定），不自研按钮/表格/弹窗/表单/进度条等通用件。
2. **领域组件在 RCL 自研**（分段列表、详情面板、差异对比、进度看板、违规徽标等）——第三方库未覆盖且为产品核心。
3. **原则**：经确认安全（维护活跃、来源可信）的 NuGet 库即可直接使用，不重复造轮子。

## 理由

- 个人项目把地基外包给成熟库（双端支持、主题系统、暗色模式、可访问性基础），把精力集中在编辑器等差异化核心。
- 选 MudBlazor 而非 Ant Design Blazor / Radzen：WASM + MAUI 双端支持已验证，主题可定制（满足自定义语义色与暗色需求），维护活跃。
- 领域组件无法外包：第三方库无 CAT 类组件，且是产品差异化所在。

## 后果

- 正向：开发速度快、UI 质量基线高、双端一致性强。
- 反向：依赖 MudBlazor 生态，升级需全仓（RCL + 两端）同步验证；主题能力受其限制。
- 若未来 MudBlazor 不可用：通用层替换成本高；领域组件（自研）不受影响，可复用。

## 替代方案

- 纯自研：周期长、UI 质量不稳定（拒绝）。
- 纯第三方：设计语言被绑定，且编辑器核心仍需自研，未省掉最大工作量（拒绝）。
