# Roadmap To Docs (MyTranslator)

项目级技能：把 ROADMAP 中的任务条目转化为 `docs/back/` 下的前后端接口约定文档，落实 AGENTS.md「所有前端与后端交互的约定，在 docs/back 下以 md 格式保存」。核心流程：定位任务 → 读取两侧需求 → 澄清契约 → 撰写文档 → 交叉校验 → 收尾。

## 1. 定位任务（必须）

- 在 `ROADMAP.md` 中定位用户指定的任务条目：按标题关键词或「后端：X / 前端：X」名称精确匹配，不凭记忆猜测。
- 任务通常成对出现：后端条目（功能实现 + 「更新 docs/back XXX 接口约定」子项）+ 一个或多个前端条目（对应界面）。本技能按功能配对，产出**一份**共享契约文档覆盖两端。
- 配对规则：按功能名与验收标准判断，允许一对多（如「后端：任务管理与开放 REST 接口」同时对应「前端：翻译编辑器基础」「前端：任务管理与进度看板、Token 管理页」）。
- 无「更新 docs/back」子项的任务（纯前端客户端移植、Docker、GHA 等）不涉及前后端契约：明确告知用户「无需产出约定文档」，不产出。

## 2. 读取输入（必须）

写文档前读取以下文件（本会话已读且未修改的可跳过）：

- `ROADMAP.md` 中该任务的后端条目 + 全部关联前端条目全文（含子项清单与验收标准）
- `docs/back/` 全部既有文档 —— 新文档必须与文档家族格式一致，且不得改变既有字段语义（格式见 `references/doc-pattern.md`）
- `CONTEXT.md` —— 领域术语表；文档用词必须使用其中词汇（确认≠完成、违规≠错误、审核意见≠评分/报告）
- `docs/adr/` 相关 ADR（尤其 0002 占位符/标记提取模型）
- `docs/front/` 交互规范 —— 只提取与接口相关的交互约束（保存时机、确认状态流转、错误提示来源），不读视觉细节

## 3. 澄清契约（必须）

对「前后端必须一致且需求未明确」的关键契约决策向用户提问，一次只问一组问题（3~5 个），拿到答复后再继续：

- 接口路径与资源形状、请求/响应字段命名、状态与枚举取值
- 分页方式（游标/偏移）、错误码与 HTTP 状态、鉴权与权限要求
- 并发与一致性：乐观锁 `version`、提取修订、保存冲突处理
- 边界行为：空值语义（`null` vs 空串）、依赖未就绪时行为（如 TM 未配置）、失败与重试策略

提问纪律：**既有约定能覆盖的问题不得提问**（沿用 `docs/back` 家族约定）；每个问题给出推荐默认值；需求已明确的点不问。

## 4. 撰写文档（必须）

- 输出到 `docs/back/<功能名>接口约定.md`，文件名与 ROADMAP「更新 docs/back XXX 接口约定」子项一致。
- 严格遵循 `references/doc-pattern.md` 的骨架、通用约定与交叉引用规则。
- 文档必须足以让前后端各自独立开发，且第三方按文档可独立对接（无内外部接口区分）。
- 前端相关约束只记录接口行为与数据契约（字段、状态、时序、错误码映射）；UI 视觉规范留给 `docs/front`，不得写入本文档。

## 5. 交叉校验（必须）

成稿后逐项核对：

- 术语全部来自 `CONTEXT.md`；错误码与《鉴权与基础接口约定》一致（Problem Details、401 语义等）。
- 不改变既有文档字段语义；新增内容只做扩展（新增字段/新资源），既有字段只读性、占位符语法、受保护块语义不变。
- 占位符/标记表/受保护块/提取修订概念与 ADR-0002 及《文件导入拆解与导出接口约定》一致。
- 后端条目与前端条目的验收标准均被本文档覆盖；文档自检能回答每条验收标准。
- 错误码表齐全：每种可预期失败都有 HTTP 状态 + 机器可读错误码 + 说明。

## 6. 收尾（必须）

- 勾选 ROADMAP 中该任务的「更新 docs/back XXX 接口约定」子项（**仅该子项**；实现类子项不得勾选，保证 ROADMAP 状态真实可审计）。
- 交付说明列出：产出文档路径、关键契约决策、澄清阶段用户确认过的点、未覆盖或预留后续文档的内容。

## 禁止事项

- 禁止不读既有 `docs/back` 文档直接按自创格式撰写。
- 禁止改写既有文档的字段语义（只允许扩展）。
- 禁止引入 `CONTEXT.md` 之外的术语。
- 禁止把 `docs/front` 的视觉/组件规范写入 `docs/back`。
- 禁止跳过澄清步骤直接写文档（关键契约歧义必须先确认）。
